## 2.6 P0 API 字段草案

本稿基于以下文档整理：

- `docs/2.4-MVP-API-范围冻结稿.md`
- `docs/2.5-P0-数据表实现稿.md`

目标是为当前阶段 `P0 API` 提供统一的请求字段、响应字段和列表筛选参数草案，便于后续接口设计、前端联调和数据库字段映射。

当前阶段接口设计遵循以下原则：

- 只覆盖冻结稿中的 `P0 API`。
- 优先定义可稳定联调的字段，不为远期能力提前增加复杂度。
- 首页优先使用聚合接口，不要求前端自行拼装多个资源接口。
- 状态变更优先使用动作型接口，如 `start`、`submit`、`resolve`。
- 样本结果中的 `raw_value` 与 `normalized_value` 使用 `JSON` 结构返回。
- 当前阶段允许 `operator_id`、`entered_by`、`queued_by`、`reported_by`、`resolved_by` 等归属字段显式传参，后续认证接入后再改为后端自动注入。
- 当前阶段 `sample_code` 允许人工填写，但后端必须负责唯一性校验。
- 当前阶段 `sample_results` 主流程只使用 `status` 字段驱动，`review_status` 保留为后续扩展字段。

### 2.6.1 统一响应结构建议

**成功响应**

```json
{
  "data": {}
}
```

**列表响应**

```json
{
  "data": [],
  "meta": {
    "page": 1,
    "page_size": 20,
    "total": 0
  }
}
```

**错误响应**

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "sample_type is required"
  }
}
```

### 2.6.2 Dashboard

#### `GET /api/dashboard/summary`

**用途**

- 返回首页摘要卡片数据。

**请求参数**

- 无。

**响应草案**

```json
{
  "data": {
    "pending_samples": 128,
    "today_inspection_tasks": 14,
    "open_exceptions": 3,
    "queued_analysis_jobs": 9
  }
}
```

**字段说明**

- `pending_samples`：待处理样本数。
- `today_inspection_tasks`：今日巡检任务数。
- `open_exceptions`：未处理异常数。
- `queued_analysis_jobs`：排队中或处理中分析任务数。

#### `POST /api/analysis-jobs/{id}/retry`

**用途**

- 基于失败任务重新发起分析，并新建一条 `queued` 任务记录。

**路径参数**

- `id`：原失败任务 ID。

**响应草案**

```json
{
  "data": {
    "id": 502,
    "sample_id": 101,
    "job_type": "quality_assessment",
    "status": "queued",
    "queued_at": "2026-03-10 18:15:00"
  }
}
```

**说明**

- 原失败任务保留原有 `failed` 状态与失败信息，不会被重置为 `queued`。
- retry 语义是“新建一条任务记录”，而不是“复活原任务”。

### 2.6.8 当前阶段接口风格约束

- 列表查询统一采用分页参数：`page`、`page_size`。
- 列表筛选统一通过 query string 传递。
- 创建接口只返回最小必要数据，完整信息通过详情接口获取。
- 状态推进优先通过动作接口完成，不允许前端直接任意修改状态字段。
- 样本结果作为结构化载荷处理，接口层保持 `JSON` 表达，不提前固定为大量专用列。

### 2.6.9 当前阶段已确认的接口决策

- `sample_code` 当前阶段允许人工填写，由后端执行唯一性校验。
- `operator_id`、`entered_by`、`queued_by`、`reported_by`、`resolved_by` 等字段当前阶段允许显式传参，后续再逐步切换为认证态注入。
- `sample_results` 当前阶段主流程只使用 `status` 字段，`review_status` 保留为后续扩展字段。
- `resolve_note` 当前阶段可进入日志或事件记录，不强制写入主表。
- `analysis_jobs` 当前阶段是过程资源，不自动等同于最终业务结果；`result_summary` 与 `error_message` 用于帮助样本详情页给出后续处理引导。
