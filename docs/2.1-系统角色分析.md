## 2.1 系统角色分析

本节描述系统的使用角色、职责边界与阶段性能力范围。

重要说明：本文档同时包含当前阶段可落地的角色能力，以及后续可扩展方向。当前项目应优先围绕 Web 工作台完成最小业务闭环，不默认承诺离线巡检、北斗围栏、数字签名、复杂外部集成等高成本能力。

### 2.1.1 当前阶段角色概览

| 角色名称 | 当前核心职责 | 当前优先支持的能力 |
| --- | --- | --- |
| 巡检员 | 执行巡检任务、采集现场信息、提交样本与异常记录 | 任务查看、状态更新、基础数据录入、照片上传入口、异常上报 |
| 实验分析员 | 处理样本流转、录入实验结果、查看分析状态 | 收样登记、样本检索、结果录入、质量复核、分析任务查看 |
| 系统管理员 | 维护系统运行、查看全局状态、管理基础配置 | 用户与角色管理、参数配置、审计查看、模块状态总览 |

### 2.1.2 巡检员 (Field Inspector)

**MVP 核心职责**

- 接收巡检任务，查看任务地点、时限、说明与基础作业要求。
- 在执行过程中记录巡检状态，提交样本、备注和现场异常。
- 录入必要的环境参数与样本标识，尽量减少自由文本输入。

**建议优先支持的功能**

- 任务列表：待执行、进行中、已提交、已完成。
- 任务详情：巡检对象、地点描述、时间要求、注意事项。
- 基础采集：样本编号、照片、备注、环境参数。
- 异常上报：设备异常、环境异常、样本异常的分类记录。

**后续增强方向**

- 扫码自动关联样本编号。
- 更适合平板和手机的巡检提交流程。
- 弱网条件下的临时缓存与补传。

**远期规划能力**

- 离线数据库与自动冲突合并。
- GPS/北斗地理围栏校验。
- 数字签名、防篡改取证链路。
- 视频采集与复杂多媒体作业流程。

### 2.1.3 实验与分析人员 (Analyst)

**MVP 核心职责**

- 接收样本并完成基础入库审核。
- 记录实验结果、处理备注与质量复核结论。
- 查看分析任务状态与结果摘要。

**建议优先支持的功能**

- 样本列表与组合筛选。
- 样本详情查看，包括来源任务、基础属性与处理状态。
- 实验结果录入，包括数值、结论、备注和复核状态。
- 分析任务查看，包括待处理、处理中、成功、失败等状态。

**后续增强方向**

- 批量收样、批次管理与库位分配。
- 图片查看、基础质量标记与异常说明。
- 与 Python 分析模块的结果联动展示。

**远期规划能力**

- 复杂标注工具（矩形框、多边形、语义标签）。
- AI 识别纠偏与二次运行闭环。
- 自动生成多格式专业报告。
- 高性能影像浏览与流媒体回放。

### 2.1.4 系统管理员 (Admin)

**MVP 核心职责**

- 维护用户访问边界与基础角色权限。
- 管理系统参数、字典项和任务模板。
- 查看关键操作日志与运行状态摘要。

**建议优先支持的功能**

- 基础 RBAC：按角色控制模块可见性与关键操作权限。
- 参数配置：样本类型、任务类别、异常等级等字典信息。
- 日志审计：关键增删改、状态回退、结果复核等操作留痕。
- 总览查看：任务数量、异常数量、分析任务积压等指标摘要。

**后续增强方向**

- 更细粒度的数据权限。
- 更丰富的任务模板与调度配置。
- 失败任务重试、状态巡检与基础运维看板。

**远期规划能力**

- 智能派单与周期调度。
- 模型版本管理与灰度发布。
- 第三方平台同步与外部密钥管理。
- 数据回滚、复杂容灾与合规审计体系。

### 2.1.5 角色设计原则

- 当前优先服务于内部工作台使用场景，而非一次性覆盖所有现场与科研扩展能力。
- 角色边界应围绕业务对象建立：巡检任务、样本、实验结果、异常事件、分析任务。
- 当前阶段优先保证“可操作、可追踪、可审计”，再逐步扩展“智能化、自动化、强离线”。
