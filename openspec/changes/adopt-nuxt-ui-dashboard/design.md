## 上下文

当前 `frontend` 目录仍是 Nuxt 最小启动项目，只包含默认欢迎页，尚未形成适合业务系统的页面壳、导航、仪表盘首页和模块入口。项目已经确定采用 Nuxt 4、pnpm、Node/Nitro、Nginx 反向代理到 3000 端口、Docker Compose、MariaDB 和 Redis，因此本次前端升级应以“替换前端起点并保留现有运行模型”为原则，而不是重新设计整套部署架构。

Nuxt UI Dashboard 模板比当前项目更接近海洋样本与巡检系统的使用形态：系统主要面向内部人员，包含侧边导航、总览仪表盘、列表页、状态卡片、设置页和多模块工作台。模板提供成熟的后台交互骨架，但其默认品牌、文案、模块分组和页面语义需要改造成项目专用结构。

## 目标 / 非目标

**目标：**
- 用 Nuxt UI Dashboard 替换当前最小前端壳，建立可扩展的后台工作台基础。
- 将导航、首页、页面分组和术语调整为海洋样本与巡检系统语境。
- 保持 Nuxt 4 Node/Nitro、Nginx、Docker Compose 和 pnpm 工作流兼容。
- 为后续样本管理、巡检任务、仪器监控、统计报表和系统设置页面预留清晰入口。
- 确保布局在桌面端和平板/手机巡检场景下都可用。

**非目标：**
- 不在本次变更中完成全部业务页面和真实数据接口。
- 不改变 PHP、Python、MariaDB、Redis 的职责边界。
- 不引入新的前端框架体系或切换到静态部署模式。
- 不在本次变更中实现图像处理、告警推送或复杂权限策略本身。

## 决策

### 决策 1：采用 Nuxt UI Dashboard 作为前端基础模板
- 选择原因：模板天然适合后台管理台场景，已有成熟的导航、工作区、卡片和页面结构，能比从零搭建更快落地 MVP。
- 放弃方案：
  - `nuxt-shadcn-dashboard`：视觉更灵活，但需要手动统一更多组件规范和管理台细节。
  - 保留当前最小 Nuxt 项目逐步手写：初始工作量更大，重复搭建基础设施。

### 决策 2：保留现有 Node/Nitro + Nginx 反向代理部署模型
- 选择原因：当前项目已明确通过 Nginx 反向代理到 Nuxt 3000 端口，Docker Compose 与前端开发流已经围绕该模型建立。
- 放弃方案：
  - 改为静态导出：与当前已确定的 Nuxt 运行方式不一致，也会限制后续 SSR/服务端能力。
  - 直接绕过 Nginx 暴露 Nuxt：不利于统一入口管理与后续 API 反代。

### 决策 3：先做“工作台适配”，后做“业务深度实现”
- 选择原因：当前最大瓶颈是前端基础壳缺失，而不是单个业务页面的细节。先把模板改造成适合本项目的 IA 和页面框架，后续业务模块才能高效接入。
- 放弃方案：
  - 在模板接入同时实现完整业务流：范围过大，容易拖慢前端基础替换。

### 决策 4：首页与导航围绕业务工作区组织，而不是模板原始分组
- 选择原因：模板默认导航不贴合海洋样本/巡检系统语义，需要改为项目使用者更容易理解的模块结构。
- 拟采用的一级工作区：总览、样本管理、巡检任务、仪器监控、统计报表、系统设置。
- 放弃方案：
  - 保留模板默认模块名称：会增加后续认知负担并削弱项目适配度。

### 决策 5：前端先使用占位数据与静态视图验证结构
- 选择原因：PHP API、Python 分析和 Redis 异步流尚未在前端侧形成完整业务接口，先用静态或 mock 数据建立页面结构更符合 MVP 节奏。
- 放弃方案：
  - 强依赖真实接口后再替换模板：会让前端基础改造被后端进度阻塞。

## 风险 / 权衡

- 模板内置的 UI 组织方式可能与项目长期视觉体系不完全一致 → 先接受其管理台骨架价值，后续再做视觉细化。
- 过度沿用模板示例页面可能让信息架构偏离真实业务 → 在接入早期就替换导航、首页文案和模块命名。
- 模板依赖增加会带来一定升级和学习成本 → 保持依赖范围聚焦在模板所需基础组件，避免额外引入无关扩展。
- 移动端巡检场景若只按桌面后台设计，现场可用性会不足 → 所有一级页面壳和导航交互都需要考虑窄屏使用方式。

## 迁移计划

1. 在现有 `frontend` 项目中引入 Nuxt UI Dashboard 模板结构与依赖。
2. 清理最小示例页面，建立项目专用布局、导航和首页。
3. 将主要工作区映射为业务模块入口，并使用占位数据验证页面结构。
4. 校准 Docker、pnpm 和 Nginx 下的开发/运行一致性。
5. 验证首页、主要导航和基础响应式布局可正常访问；如不满足预期，可回退到当前最小 Nuxt 项目骨架。

## 开放问题

- 是否在本次模板适配中同步引入认证占位态，还是仅保留单用户开发入口。
- 是否要在首页直接暴露“待处理样本”“巡检异常”“分析任务队列”等关键指标卡片。
- 是否需要保留模板中的命令面板、通知区等高级交互，还是先做精简版后台框架。
