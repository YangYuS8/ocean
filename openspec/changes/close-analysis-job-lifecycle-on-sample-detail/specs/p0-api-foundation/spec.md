## 新增需求

### 需求:P0 分析任务接口必须支持最小状态推进动作
系统必须提供围绕分析任务的最小状态推进动作，以便在当前 MVP 阶段让分析任务从“已创建记录”演进为“可解释的过程状态”。

#### 场景:开始分析任务
- **当** 前端或受控调用方请求分析任务开始动作
- **那么** 系统必须仅允许将状态为 `queued` 的分析任务推进到 `running`
- **那么** 系统必须记录 `started_at`

#### 场景:标记分析任务成功
- **当** 前端或受控调用方请求分析任务成功完成动作
- **那么** 系统必须仅允许将状态为 `running` 的分析任务推进到 `succeeded`
- **那么** 系统必须记录 `finished_at`
- **那么** 系统必须在可用时保存 `result_summary`

#### 场景:标记分析任务失败
- **当** 前端或受控调用方请求分析任务失败完成动作
- **那么** 系统必须仅允许将状态为 `running` 的分析任务推进到 `failed`
- **那么** 系统必须记录 `finished_at`
- **那么** 系统必须在可用时保存 `error_message`

#### 场景:取消分析任务
- **当** 前端或受控调用方请求分析任务取消动作
- **那么** 系统必须仅允许将状态为 `queued` 的分析任务推进到 `cancelled`

## 修改需求

### 需求:P0 分析任务接口必须支持异步任务记录与查询
系统必须提供分析任务创建、查询和最小状态推进接口，以支撑后续 Redis/Python 异步处理链路的渐进接入；在当前 MVP 阶段，前端最小工作流必须支持围绕样本详情页发起分析任务、查看状态、在成功或失败后获得后续处理提示，并对失败任务执行重新发起。

#### 场景:创建分析任务
- **当** 前端请求 `POST /api/analysis-jobs`
- **那么** 系统必须创建分析任务记录，并将初始状态设置为 `queued`
- **那么** 系统必须要求提供 `sample_id` 和 `job_type`
- **那么** 当前 MVP 前端工作流必须允许在样本详情页内完成该动作

#### 场景:查询分析任务列表
- **当** 前端请求 `GET /api/analysis-jobs`
- **那么** 系统必须返回分析任务列表，并支持按样本、任务类型、状态、发起人和入队时间范围筛选
- **那么** 当前 MVP 前端工作流必须允许围绕当前样本过滤并展示相关任务状态

#### 场景:查询分析任务详情
- **当** 前端请求 `GET /api/analysis-jobs/{id}`
- **那么** 系统必须返回任务状态、参数、结果摘要和错误信息

#### 场景:重新发起失败任务
- **当** 前端请求分析任务重新发起动作
- **那么** 系统必须仅允许基于状态为 `failed` 的任务执行该动作
- **那么** 系统必须保留原任务记录不变
- **那么** 系统必须创建新的分析任务记录，并将初始状态设置为 `queued`
- **那么** 当前 MVP 前端工作流必须允许在样本详情页内完成该动作
