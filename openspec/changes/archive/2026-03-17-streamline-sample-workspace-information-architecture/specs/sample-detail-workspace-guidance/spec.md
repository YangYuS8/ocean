## 修改需求

### 需求:样本详情必须提供工作台级处理摘要
系统必须在样本详情页中提供工作台级处理摘要，用于概括当前样本的处理态势，而不能要求用户自行阅读多个区块后再拼出整体状态；该摘要必须位于结果、异常和分析任务等具体处理区块之前，作为页面级信息架构的首要层级之一。

#### 场景:进入样本详情页查看当前态势
- **当** 用户进入样本详情页
- **那么** 系统必须展示当前样本状态、结果录入情况、异常情况和分析任务情况的最小摘要
- **那么** 该摘要必须先于具体处理区块出现，帮助用户先理解整体态势再进入细节操作

### 需求:样本详情必须提供推荐下一步
系统必须在样本详情页中根据当前样本的已有状态和关联数据，向用户提供最小推荐下一步，以降低工作台的决策成本；推荐下一步必须与页面级摘要和风险提示保持邻近，禁止把主推荐动作只放在单一区块内部。

#### 场景:样本仍缺少结果记录
- **当** 当前样本尚无结果记录
- **那么** 系统必须将结果录入表达为推荐下一步之一

#### 场景:样本存在失败分析任务
- **当** 当前样本存在失败的分析任务
- **那么** 系统必须提示用户可优先重新发起分析或记录异常

### 需求:样本详情必须明确表达当前阻塞或风险提示
系统必须在样本详情页中把会影响当前样本后续处理的风险或阻塞信息显式表达出来，而不是仅依赖用户逐区块发现问题；风险提示必须在页面信息层级上高于具体处理区块，并与推荐下一步共同构成进入页面后的主判断区域。

#### 场景:样本存在未解决异常
- **当** 当前样本存在 `open` 状态的异常
- **那么** 系统必须将未解决异常显示为当前风险或阻塞提示之一

#### 场景:样本存在执行中的分析任务
- **当** 当前样本存在 `queued` 或 `running` 状态的分析任务
- **那么** 系统必须向用户提示当前仍有分析过程在进行中或待完成
