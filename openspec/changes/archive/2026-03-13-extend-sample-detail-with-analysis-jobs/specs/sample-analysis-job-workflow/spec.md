## 新增需求

### 需求:样本详情必须提供样本级分析任务区块
系统必须在样本详情页内提供分析任务区块，允许用户围绕当前样本查看分析任务列表、发起分析任务并查看任务状态，而不能要求其跳转到独立分析任务模块才能完成当前样本处理链。

#### 场景:查看样本分析任务区块
- **当** 用户进入样本详情页
- **那么** 系统必须展示当前样本的分析任务区块

### 需求:分析任务第一版必须使用极小任务类型集合
系统必须将第一版分析任务 `job_type` 收敛为少量固定选项，以降低任务发起门槛并保持 MVP 收敛。

#### 场景:选择分析任务类型
- **当** 用户在分析任务发起表单中选择任务类型
- **那么** 系统必须至少提供 `quality_assessment` 与 `anomaly_scan` 两个选项

### 需求:分析任务第一版必须支持最小发起动作
系统必须允许用户在样本详情页内围绕当前样本创建新的分析任务记录。

#### 场景:发起分析任务
- **当** 用户在样本详情页提交合法的分析任务表单
- **那么** 系统必须调用现有分析任务创建接口创建任务记录
- **那么** 系统必须将任务初始状态设置为 `queued`
- **那么** 系统必须刷新当前样本的分析任务列表并展示成功反馈

### 需求:分析任务区块必须提供状态查看能力
系统必须在样本详情页内展示当前样本的分析任务列表和最小状态信息，以支撑 MVP 中的“分析状态”环节。

#### 场景:查看样本分析任务列表
- **当** 用户在样本详情页查看分析任务区块
- **那么** 系统必须展示当前样本已有分析任务的列表
- **那么** 系统必须至少展示任务类型、状态、发起人和入队时间

#### 场景:展示完成或失败任务信息
- **当** 分析任务状态为成功或失败
- **那么** 系统必须在可用时展示结果摘要或错误信息

## 修改需求

### 需求:样本详情必须作为结果与后续动作的挂载中心
系统必须提供样本详情页，并在其中展示样本基本信息、结果列表、结果录入入口、样本级异常处理区块以及样本级分析任务区块，为样本处理链提供连续的 MVP 工作流。

#### 场景:在样本详情页继续处理样本
- **当** 用户需要继续推进样本处理链
- **那么** 系统必须允许其在样本详情页直接发起结果录入、样本级异常处理和样本级分析任务，而不是要求跳转到独立结果、异常或分析任务模块

### 需求:P0 分析任务接口必须支持异步任务记录与查询
系统必须提供分析任务创建和查询接口，以支撑后续 Redis/Python 异步处理链路的渐进接入；在当前 MVP 阶段，前端最小工作流必须支持围绕样本详情页发起分析任务并查看状态。

#### 场景:创建分析任务
- **当** 前端请求 `POST /api/analysis-jobs`
- **那么** 系统必须创建分析任务记录，并将初始状态设置为 `queued`
- **那么** 系统必须要求提供 `sample_id` 和 `job_type`
- **那么** 当前 MVP 前端工作流必须允许在样本详情页内完成该动作

#### 场景:查询分析任务列表
- **当** 前端请求 `GET /api/analysis-jobs`
- **那么** 系统必须返回分析任务列表，并支持按样本、任务类型、状态、发起人和入队时间范围筛选
- **那么** 当前 MVP 前端工作流必须允许围绕当前样本过滤并展示相关任务状态
