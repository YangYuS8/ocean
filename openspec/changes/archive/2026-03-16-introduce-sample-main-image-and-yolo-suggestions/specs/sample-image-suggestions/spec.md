## ADDED Requirements

### 需求:样本必须支持唯一主图
系统必须允许用户为每个样本维护唯一的一张主图，并将该主图作为自动检测建议的当前输入对象。

#### 场景:为样本设置主图
- **当** 用户为某个样本上传或指定主图
- **那么** 系统必须保存该图片为当前样本唯一主图
- **并且** 后续自动检测必须默认针对该主图执行

#### 场景:读取已有主图
- **当** 前端请求样本详情或图片管理数据
- **那么** 系统必须返回当前主图标识及其可展示的图片信息

### 需求:系统必须提供 YOLO 建议结果查询能力
系统必须为样本当前主图提供可查询的 YOLO 建议结果，建议结果必须与正式业务结果分离，并包含人工判断所需的基础信息。

#### 场景:查询已有建议结果
- **当** 当前主图已经存在最新的 YOLO 推理结果
- **那么** 系统必须返回建议摘要
- **并且** 返回内容必须包含是否有发现、类别计数、置信度概览、结果生成时间以及必要的结构化建议数据

#### 场景:建议结果尚未生成
- **当** 前端查询样本主图建议结果但后台尚未生成可用结果
- **那么** 系统必须返回明确的待处理或无结果状态
- **并且** 不得将缺失建议结果误报为正式结果或主图结论

#### 场景:检测成功但没有发现目标
- **当** YOLO 已完成推理但没有识别出满足阈值的目标
- **那么** 系统必须将该次检测记录为成功的空建议
- **并且** 前端必须将其展示为“未检测到明确目标”之类的参考语义，而不是失败

### 需求:系统必须支持异步触发或刷新 YOLO 建议
系统必须支持通过业务接口手动触发当前主图的 YOLO 建议生成或刷新，并通过可追踪任务避免阻塞用户操作。

#### 场景:触发建议刷新
- **当** 用户在样本工作台上对当前主图发起“运行自动检测”或“重新检测”
- **那么** 系统必须创建一个可追踪的 YOLO 分析任务交由后端处理
- **并且** 接口必须立即返回受理状态而不是等待推理完成

#### 场景:重复触发处理中任务
- **当** 当前主图已经存在进行中的 YOLO 检测任务
- **那么** 系统必须阻止无限制重复创建新任务
- **并且** 前端必须向用户展示当前检测中的状态

#### 场景:主图替换后旧建议失效
- **当** 样本主图被替换
- **那么** 系统必须将旧主图对应的建议视为历史记录
- **并且** 页面不得继续将其展示为当前有效建议

### 需求:前端必须以人工确认为中心展示建议结果
Nuxt 前端必须在桌面端和移动端展示主图状态与 YOLO 建议结果，并明确区分“算法建议”和“人工确认结果”。

#### 场景:移动端查看建议摘要
- **当** 巡检人员在手机或平板上打开 `samples/:id`
- **那么** 前端必须优先展示主图、建议状态和关键操作按钮
- **并且** 详细建议信息必须可以通过展开或二级视图查看

#### 场景:页面同时呈现建议与任务历史
- **当** 页面已经存在自动检测建议卡片和分析任务记录区
- **那么** 自动检测建议必须优先呈现当前主图的最新相关建议
- **并且** 分析任务记录必须继续保留历史过程状态而不替代建议消费层

#### 场景:人工依据建议继续后续处理
- **当** 用户查看自动检测建议后继续录入正式结果或处理异常
- **那么** 页面文案必须明确该建议仅供人工参考
- **并且** 系统不得在没有人工确认的情况下自动写入正式结果
