## MODIFIED Requirements

### 需求:P0 数据库基础必须可初始化
系统必须在 MariaDB 中提供 P0 阶段所需的核心数据表、索引和基础角色初始化数据，以支撑巡检任务、样本、结果、异常和分析任务的真实落库。

#### 场景:初始化核心表结构
- **当** 开发或部署环境执行 P0 数据库初始化流程
- **那么** 系统必须创建 `users`、`roles`、`user_roles`、`inspection_tasks`、`samples`、`sample_results`、`exceptions`、`analysis_jobs` 八张核心表
- **那么** 系统必须为唯一键、查询索引和明确单资源关联字段建立与设计一致的数据库约束
- **那么** 当前长期主路径必须以 Laravel migration 表达这些数据库结构

#### 场景:初始化基础角色数据
- **当** 数据库初始化完成
- **那么** 系统必须提供 `inspector`、`analyst`、`admin` 三类基础角色数据
- **那么** 当前长期主路径必须以 Laravel seeder 表达这些初始化数据

### 需求:P0 工作台必须提供首页摘要接口
系统必须通过 PHP `/api/` 提供首页摘要接口，向 Nuxt 工作台返回待处理样本数、今日巡检任务数、未处理异常数和分析任务队列数。

#### 场景:获取首页摘要
- **当** 前端请求 `GET /api/dashboard/summary`
- **那么** 系统必须返回 `pending_samples`、`today_inspection_tasks`、`open_exceptions`、`queued_analysis_jobs` 四项摘要数据
- **那么** 该接口在 Laravel 迁移后仍必须保持现有路径和字段语义不变

### 需求:P0 巡检任务接口必须支持查询与状态推进
系统必须提供巡检任务查询接口和最小状态推进动作，以支撑前端工作台执行任务闭环。

#### 场景:查询巡检任务列表
- **当** 前端请求 `GET /api/inspection-tasks`
- **那么** 系统必须返回任务列表，并支持按状态、指派人、任务类型、计划日期范围和关键字进行筛选
- **那么** Laravel 迁移后必须保持该接口路径和筛选语义不变

#### 场景:查询巡检任务详情
- **当** 前端请求 `GET /api/inspection-tasks/{id}`
- **那么** 系统必须返回任务详情、当前状态、时间字段和关联操作人信息

#### 场景:开始巡检任务
- **当** 前端请求 `POST /api/inspection-tasks/{id}/start`
- **那么** 系统必须仅允许将任务从 `assigned` 推进到 `in_progress`

#### 场景:提交巡检任务
- **当** 前端请求 `POST /api/inspection-tasks/{id}/submit`
- **那么** 系统必须仅允许将任务从 `in_progress` 推进到 `submitted`

### 需求:P0 样本接口必须支持登记与查询
系统必须提供样本登记、列表查询和详情查看接口，以支撑样本成为后续结果、异常和分析任务的核心关联对象。

#### 场景:登记样本
- **当** 前端请求 `POST /api/samples`
- **那么** 系统必须创建样本记录并将初始状态设置为 `registered`
- **那么** 系统必须校验 `sample_code` 的唯一性

#### 场景:查询样本列表
- **当** 前端请求 `GET /api/samples`
- **那么** 系统必须返回样本列表，并支持按样本编号、来源任务、样本类型、状态、采集人和采集日期范围筛选

#### 场景:查询样本详情
- **当** 前端请求 `GET /api/samples/{id}`
- **那么** 系统必须返回样本详情及其关联任务、采集信息和状态字段

### 需求:P0 样本结果接口必须支持结构化结果记录
系统必须提供围绕样本的结果查询和新增接口，并使用结构化 JSON 载荷表示检测结果。

#### 场景:新增样本结果
- **当** 前端请求 `POST /api/samples/{id}/results`
- **那么** 系统必须创建新的样本结果记录
- **那么** 系统必须将结果初始状态设置为 `draft`
- **那么** 系统必须接受 `raw_value` 和 `normalized_value` 的 JSON 数据结构

#### 场景:查询样本结果列表
- **当** 前端请求 `GET /api/samples/{id}/results`
- **那么** 系统必须返回该样本下的结果列表，并支持按结果类型和状态筛选

### 需求:P0 异常接口必须支持记录与处理
系统必须提供异常列表、异常创建和异常解决接口，以支撑任务、样本和结果相关问题的独立处理。

#### 场景:记录异常
- **当** 前端请求 `POST /api/exceptions`
- **那么** 系统必须创建异常记录，并要求提供 `resource_type`、`resource_id`、`category` 和 `title`
- **那么** 系统必须将异常初始状态设置为 `open`

#### 场景:查询异常列表
- **当** 前端请求 `GET /api/exceptions`
- **那么** 系统必须返回异常列表，并支持按资源类型、资源 ID、分类、级别、状态、上报人和创建时间范围筛选

#### 场景:解决异常
- **当** 前端请求 `POST /api/exceptions/{id}/resolve`
- **那么** 系统必须仅允许将异常从 `open` 推进到 `resolved`

### 需求:P0 分析任务接口必须支持异步任务记录与查询
系统必须提供分析任务创建和查询接口，以支撑后续 Redis/Python 异步处理链路的渐进接入。

#### 场景:创建分析任务
- **当** 前端请求 `POST /api/analysis-jobs`
- **那么** 系统必须创建分析任务记录，并将初始状态设置为 `queued`
- **那么** 系统必须要求提供 `sample_id` 和 `job_type`

#### 场景:查询分析任务列表
- **当** 前端请求 `GET /api/analysis-jobs`
- **那么** 系统必须返回分析任务列表，并支持按样本、任务类型、状态、发起人和入队时间范围筛选

#### 场景:查询分析任务详情
- **当** 前端请求 `GET /api/analysis-jobs/{id}`
- **那么** 系统必须返回任务状态、参数、结果摘要和错误信息

### 需求:P0 接口必须保持统一响应约定
系统必须为 P0 API 提供统一的成功响应、列表响应和错误响应结构，以降低前后端联调复杂度。

#### 场景:返回列表响应
- **当** 前端请求任一 P0 列表接口
- **那么** 系统必须返回 `data` 数组
- **那么** 系统必须返回包含 `page`、`page_size` 和 `total` 的 `meta` 分页信息

#### 场景:返回错误响应
- **当** 请求参数不合法或资源不存在
- **那么** 系统必须返回包含 `code` 和 `message` 的统一错误结构
