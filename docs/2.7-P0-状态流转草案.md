## 2.7 P0 状态流转草案

本稿用于冻结当前阶段核心业务对象的状态流转规则，作为以下设计的共同依据：

- API 动作接口设计
- 数据表状态字段定义
- 前端按钮与交互约束
- 后端状态校验逻辑

本稿基于以下文档：

- `docs/2.4-MVP-API-范围冻结稿.md`
- `docs/2.5-P0-数据表实现稿.md`
- `docs/2.6-P0-API-字段草案.md`

当前阶段的原则不是把所有远期状态都一次性设计完整，而是先把 `P0` 主链路中的可执行、可校验、可追踪状态变化固定下来。

```text
P0 主链路状态

inspection_tasks  ->  samples  ->  sample_results
        |                |               |
        v                v               v
    exceptions       exceptions      exceptions
        \
         \---------------------------------> analysis_jobs
```

### 2.7.1 设计原则

- 状态变化优先通过显式动作触发，而不是允许前端任意修改 `status`。
- 当前阶段仅冻结 `P0` 所需状态，不为远期能力提前设计复杂分支。
- 每个状态都应能映射到明确的业务语义，而不是单纯技术占位。
- 进入终态后，如无明确业务动作，不允许回退。

### 2.7.2 inspection_tasks

**状态集合**

- `assigned`
- `in_progress`
- `submitted`
- `completed`
- `cancelled`

**状态图**

```text
assigned -> in_progress -> submitted -> completed
    \                             \
     \----------------------------> cancelled
```

**状态定义**

- `assigned`：任务已创建并分配，可开始执行。
- `in_progress`：任务已开始执行。
- `submitted`：任务已提交现场结果，等待进一步确认或收尾。
- `completed`：任务已完成闭环。
- `cancelled`：任务被取消，不再继续执行。

**允许的状态流转**

- `assigned -> in_progress`
- `in_progress -> submitted`
- `submitted -> completed`
- `assigned -> cancelled`
- `in_progress -> cancelled`
- `submitted -> cancelled`

**当前阶段对应动作接口**

- `POST /api/inspection-tasks/{id}/start`
  - `assigned -> in_progress`
- `POST /api/inspection-tasks/{id}/submit`
  - `in_progress -> submitted`

**P1 预留动作**

- `POST /api/inspection-tasks/{id}/complete`
  - `submitted -> completed`

**当前阶段不允许的流转**

- `assigned -> submitted`
- `assigned -> completed`
- `completed -> in_progress`
- `cancelled -> 任意非 cancelled`

### 2.7.3 samples

**状态集合**

- `registered`
- `received`
- `testing`
- `reviewed`
- `archived`
- `invalid`

**状态图**

```text
registered -> received -> testing -> reviewed -> archived
     \             \         \           \
      \             \         \-----------> invalid
       \-------------\--------------------> invalid
```

**状态定义**

- `registered`：样本已登记，尚未正式进入收样或处理。
- `received`：样本已被实验/处理侧接收。
- `testing`：样本已进入检测或分析处理阶段。
- `reviewed`：样本相关结果已完成当前阶段复核。
- `archived`：样本已归档。
- `invalid`：样本被判定无效，不再继续正常流程。

**允许的状态流转**

- `registered -> received`
- `received -> testing`
- `testing -> reviewed`
- `reviewed -> archived`
- `registered -> invalid`
- `received -> invalid`
- `testing -> invalid`
- `reviewed -> invalid`

**当前阶段实现建议**

- `POST /api/samples` 创建样本时，默认进入 `registered`
- 当前 `P0` 可暂不暴露样本状态推进动作接口，由后端在相关业务动作中内聚处理
- 当前阶段保留样本状态的内聚推进方式，不单独增加 `receive` 动作接口到 `P0`

**建议的隐式状态推进**

- 创建结果记录后，可将样本从 `received` 推进到 `testing`
- 当结果进入明确复核完成态后，可将样本推进到 `reviewed`

**当前阶段不允许的流转**

- `registered -> reviewed`
- `registered -> archived`
- `archived -> 任意非 archived`
- `invalid -> 任意非 invalid`

### 2.7.4 sample_results

**状态集合**

- `draft`
- `submitted`
- `approved`
- `rejected`

**状态图**

```text
draft -> submitted -> approved
             \
              \-> rejected
```

**状态定义**

- `draft`：结果已创建，但尚未进入确认流程。
- `submitted`：结果已提交，等待确认或复核。
- `approved`：结果已确认通过。
- `rejected`：结果被驳回或判定需重做。

**允许的状态流转**

- `draft -> submitted`
- `submitted -> approved`
- `submitted -> rejected`

**当前阶段实现建议**

- `POST /api/samples/{id}/results` 创建结果时，默认进入 `draft`
- 当前 `P0` 不强制开放完整复核接口，但状态含义先冻结，便于 P1 继续扩展

**关于 `review_status`**

- 当前阶段允许保留 `review_status` 字段作为预留，但前台主流程先以 `status` 为主
- 若后续进入 `submit-review / approve / reject` 接口阶段，再进一步明确 `status` 与 `review_status` 的职责边界
- 当前阶段正式约定：`status` 为主流程状态字段，`review_status` 不作为前台主流程判断依据

**当前阶段不允许的流转**

- `draft -> approved`
- `draft -> rejected`
- `approved -> draft`
- `rejected -> approved`

### 2.7.5 exceptions

**状态集合**

- `open`
- `resolved`
- `dismissed`

**状态图**

```text
open -> resolved
  \
   \-> dismissed
```

**状态定义**

- `open`：异常已发现，待处理。
- `resolved`：异常已处理完成。
- `dismissed`：异常被判定无需继续处理。

**允许的状态流转**

- `open -> resolved`
- `open -> dismissed`

**当前阶段对应动作接口**

- `POST /api/exceptions/{id}/resolve`
  - `open -> resolved`

**P1 预留动作**

- `POST /api/exceptions/{id}/acknowledge`
  - 当前阶段未纳入主状态集合

**当前阶段不允许的流转**

- `resolved -> open`
- `dismissed -> open`
- `resolved -> dismissed`

### 2.7.6 analysis_jobs

**状态集合**

- `queued`
- `running`
- `succeeded`
- `failed`
- `cancelled`

**状态图**

```text
queued -> running -> succeeded
   |         \
   |          \-> failed
   \
    \-> cancelled
```

**状态定义**

- `queued`：任务已创建，等待后台处理。
- `running`：任务正在执行。
- `succeeded`：任务执行成功。
- `failed`：任务执行失败。
- `cancelled`：任务被取消，不再执行。

**允许的状态流转**

- `queued -> running`
- `running -> succeeded`
- `running -> failed`
- `queued -> cancelled`

**当前阶段实现建议**

- `POST /api/analysis-jobs` 创建任务时，默认进入 `queued`
- 状态推进主要由后台任务处理器负责，而不是由前端直接控制

**P1 预留动作**

- `POST /api/analysis-jobs/{id}/retry`
  - 当前阶段正式约定为：基于失败任务新建一条任务记录，原任务保留失败历史

**当前阶段不允许的流转**

- `queued -> succeeded`
- `queued -> failed`
- `succeeded -> running`
- `cancelled -> 任意非 cancelled`

### 2.7.7 dashboard/summary

`dashboard/summary` 为聚合视图，不单独定义状态机。

其数值应由以下状态集合推导：

- 待处理样本数：来自 `samples.status`
- 今日巡检任务数：来自 `inspection_tasks.status` 与 `planned_at`
- 未处理异常数：来自 `exceptions.status = 'open'`
- 分析任务队列数：来自 `analysis_jobs.status in ('queued', 'running')`

### 2.7.8 当前阶段状态流转约束汇总

```text
inspection_tasks
assigned -> in_progress -> submitted -> completed
   \                          \
    \--------------------------> cancelled

samples
registered -> received -> testing -> reviewed -> archived
     \            \          \          \
      \------------\----------\----------> invalid

sample_results
draft -> submitted -> approved
            \
             \-> rejected

exceptions
open -> resolved
  \
   \-> dismissed

analysis_jobs
queued -> running -> succeeded
   |         \
   |          \-> failed
   \
    \-> cancelled
```

### 2.7.9 当前阶段已确认的状态相关决策

- `samples` 当前阶段不单独增加 `receive` 动作接口，样本状态推进先由后端在业务动作中内聚处理。
- `sample_results` 当前阶段以 `status` 作为主流程状态字段，`review_status` 保留为后续复核扩展字段。
- `analysis_jobs/{id}/retry` 当前阶段约定为“新建一条任务记录”，而不是重置原任务。
- `exceptions` 是否在 P1 引入 `acknowledged` 作为中间状态，仍保留到后续迭代再评估。
