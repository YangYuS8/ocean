## 新增需求

### 需求:异常状态必须参与样本详情工作台级风险提示
系统必须让样本级异常状态参与样本详情页的页面级工作台风险提示，使用户能快速识别当前样本是否存在未解决问题。

#### 场景:存在未解决异常时查看样本详情
- **当** 当前样本存在 `open` 状态的异常记录
- **那么** 系统必须在样本详情页的工作台级引导中将其表达为当前风险或阻塞提示之一

## 修改需求

### 需求:异常工作流第一版必须支持记录与解决闭环
系统必须在样本详情页内同时支持异常创建与异常解决，以形成最小可用的异常处理闭环；同时页面级工作台摘要必须能利用异常状态帮助用户判断当前样本是否存在待优先处理的问题。

#### 场景:创建异常
- **当** 用户提交合法的异常录入表单
- **那么** 系统必须调用现有异常创建接口创建异常记录
- **那么** 系统必须将异常初始状态设置为 `open`
- **那么** 系统必须刷新当前样本的异常列表并展示成功反馈

#### 场景:解决异常
- **当** 用户在样本详情页对 `open` 状态的异常执行解决动作
- **那么** 系统必须调用现有异常解决接口将异常推进到 `resolved`
- **那么** 系统必须刷新当前样本的异常列表并展示成功反馈
