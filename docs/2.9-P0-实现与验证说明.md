## 2.9 P0 迁移前实现基线

本文档记录当前仓库在迁移到 Laravel 之前已经存在的 P0 实现基线，并说明这些基线在迁移后的保留方式。

重要说明：

- 本文档描述的是迁移前轻量 PHP 实现、验证路径和运行现状。
- 这些内容用于说明“现阶段系统已经具备什么能力”，以及“Laravel 迁移时不能丢掉什么”。
- 本文档不应再被默认视为项目长期后端架构目标。
- 当前稳定边界仍以以下文档为准：
  - `docs/2.4-MVP-API-范围冻结稿.md`
  - `docs/2.5-P0-数据表实现稿.md`
  - `docs/2.6-P0-API-字段草案.md`
  - `docs/2.7-P0-状态流转草案.md`

```text
稳定约束
├─ API 范围
├─ 接口字段
├─ 状态流转
└─ 数据模型

迁移前基线
├─ 轻量 PHP API 骨架
├─ schema.sql / seed.sql
├─ 当前验证命令
└─ 当前容器联通方式
```

### 2.9.1 当前基线的作用

当前基线用于回答以下问题：

- P0 已经落地了哪些 API。
- 前端目前依赖哪些真实接口。
- 数据库当前通过什么方式初始化。
- 显式传参身份字段目前如何工作。
- Redis、Python 和 PHP 当前的边界停留在哪个层级。

Laravel 迁移时，以上信息都应被视为迁移输入，而不是被忽略的临时细节。

### 2.9.2 当前已落地能力

当前仓库中仍保留迁移前轻量 PHP API 骨架作为对照，但当前稳定运行基线已经落在 Laravel API 上，并提供了以下 P0 接口能力：

- `GET /api/dashboard/summary`
- `GET /api/inspection-tasks`
- `GET /api/inspection-tasks/{id}`
- `POST /api/inspection-tasks/{id}/start`
- `POST /api/inspection-tasks/{id}/submit`
- `GET /api/samples`
- `POST /api/samples`
- `GET /api/samples/{id}`
- `GET /api/samples/{id}/results`
- `POST /api/samples/{id}/results`
- `GET /api/exceptions`
- `POST /api/exceptions`
- `POST /api/exceptions/{id}/resolve`
- `GET /api/analysis-jobs`
- `POST /api/analysis-jobs`
- `GET /api/analysis-jobs/{id}`
- `POST /api/analysis-jobs/{id}/start`
- `POST /api/analysis-jobs/{id}/succeed`
- `POST /api/analysis-jobs/{id}/fail`
- `POST /api/analysis-jobs/{id}/cancel`
- `POST /api/analysis-jobs/{id}/retry`

当前前端首页已经通过 `/api/dashboard/summary` 接入真实摘要数据，而样本详情页中的分析任务区块也已经形成“创建、最小状态推进、失败后重新发起和后续引导”的真实工作流闭环。

### 2.9.3 当前轻量 PHP 实现形态

当前后端形态为轻量自定义结构，而非正式 PHP 框架：

- `backend/legacy-lightweight/public/index.php`：当前轻量基线 HTTP 入口
- `backend/legacy-lightweight/bootstrap.php`：当前轻量基线自定义自动加载入口
- `backend/legacy-lightweight/app/Http/ApiKernel.php`：当前轻量基线路由分发与接口映射
- `backend/legacy-lightweight/app/Infrastructure/Database.php`：当前轻量基线数据库连接入口
- `backend/legacy-lightweight/app/Service/P0ApiService.php`：当前 P0 业务逻辑集中实现
- `backend/legacy-lightweight/app/Support/*`：当前异常、响应和校验辅助代码

这些文件仍然有参考价值，但已经不再承载主运行流量。当前仓库中它们被保留在 `backend/legacy-lightweight/` 目录下，作为迁移前对照基线。

### 2.9.4 当前数据库初始化方式

当前数据库初始化的长期主路径已经是 Laravel migration / seeder；迁移前自定义 SQL 脚本和执行脚本仍作为对照基线保留：

- `backend/legacy-lightweight/database/schema.sql`
- `backend/legacy-lightweight/database/seed.sql`
- `backend/legacy-lightweight/scripts/migrate.php`
- `backend/legacy-lightweight/scripts/seed.php`

这套方式用于描述迁移前可工作的数据库基线。

当前稳定实现中的数据库初始化主路径为：

- `backend/database/migrations/`
- `backend/database/seeders/`

因此，当前 SQL 脚本应被视为迁移前参考基线，而不是当前默认初始化机制。

### 2.9.5 当前最小执行与验证路径

在当前编排环境中，当前长期主路径应通过 Laravel migration / seeder 初始化数据库：

```bash
docker compose exec php php /var/www/html/artisan migrate --force
docker compose exec php php /var/www/html/artisan db:seed --force
```

如果使用 `podman-compose`，则命令等价替换为：

```bash
podman-compose exec php php /var/www/html/artisan migrate --force
podman-compose exec php php /var/www/html/artisan db:seed --force
```

当前最小接口验证路径包括：

- `curl -s http://127.0.0.1:8080/api/dashboard/summary`
- `curl -s http://127.0.0.1:8080/api/inspection-tasks`
- 创建样本、样本结果、异常和分析任务的 POST 请求
- 围绕分析任务执行 `start -> succeed/fail -> retry` 的动作验证

这些命令在 Laravel 迁移后仍应能表达等价的验证目标，即使底层实现方式改变。

### 2.9.6 当前显式传参身份策略

当前为了避免认证系统阻塞业务 API，以下字段允许由请求显式传入：

- `operator_id`
- `entered_by`
- `queued_by`
- `reported_by`
- `resolved_by`

这是一项迁移前临时策略，不应被视为长期认证模型。

Laravel 迁移后，推荐方向是：

- 接口字段语义尽量保持不变
- 逐步改为由服务端从认证态自动注入这些值

### 2.9.7 当前 Redis 与 Python 边界

当前阶段已经明确以下事实：

- `analysis_jobs` 已在 MariaDB 中落库
- PHP 已能创建、查询并受控推进分析任务最小生命周期
- Redis 已作为异步任务边界保留在部署架构中
- Python 环境已经存在，但当前不强制要求完整消费链路全部落地
- 分析任务失败后当前已支持通过新建记录的方式重新发起，原失败任务历史会被保留

因此，当前系统的真实状态是：

```text
Nuxt
  -> PHP API
      -> MariaDB
      -> Redis (预留边界)
      -> Python (后续继续接入)
```

这意味着 Laravel 迁移时，不需要同时重做 Python 职责，只需保留 PHP 与 Redis/Python 的边界能力。
同时也意味着当前 `analysis_jobs` 在产品语义上已经是过程资源，而不是最终业务结果本身；成功或失败后的业务处理仍需回到样本结果录入与异常工作流中。

### 2.9.8 当前前端联调事实

当前前端已经形成以下联调事实：

- `frontend/app/pages/index.vue` 通过 `/api/dashboard/summary` 获取摘要数据
- 前端默认开发端口为 `3000`
- Nginx 统一入口端口为 `8080`
- phpMyAdmin 端口为 `8081`

这些入口事实在 Laravel 迁移过程中应尽量保持不变，以避免前端、运维和验证脚本同时改动。

### 2.9.9 当前基线对 Laravel 迁移的约束

Laravel 迁移时，应尽量保持以下内容不变：

- P0 API 路径
- 请求/响应字段语义
- 状态值与状态流转约束
- MariaDB 业务表语义
- Nuxt 前端对关键接口的调用方式

Laravel 迁移时可以重建或重组以下内容：

- 路由定义方式
- 请求校验方式
- 异常处理方式
- 响应封装方式
- 数据访问层与迁移脚本组织方式
- 业务服务拆分方式

### 2.9.10 当前基线文档的使用方式

后续讨论当前 P0 基线、回归验证或下一阶段扩展时，本文件应被当成：

- 迁移前快照
- 回归对照基线
- 风险识别依据

而不应被当成：

- 长期推荐后端结构
- 最终 PHP 架构说明
- 后续全部实现必须继续沿用的工具链

### 2.9.11 迁移后的保留事项

Laravel 迁移完成后，当前仍保留以下临时或过渡性策略：

- `operator_id`、`entered_by`、`queued_by`、`reported_by`、`resolved_by` 仍允许显式传参
- 数据访问当前以 Query Builder 为主，而不是一次性全面 Eloquent 化
- Redis 队列边界已保留，但完整 Python 消费链路未在本次迁移中同步重建
- `analysis_jobs` 当前已具备最小生命周期动作与失败后重新发起语义，但仍未接入完整 Python 自动消费链路
- 迁移前轻量 PHP 骨架保留在 `backend/legacy-lightweight/` 目录，仅用于对照与回归参考
