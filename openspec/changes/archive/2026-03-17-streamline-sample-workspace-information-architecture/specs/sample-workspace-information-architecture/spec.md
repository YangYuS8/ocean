## 新增需求

### 需求:样本工作区必须提供从列表到详情的分层信息架构
系统必须将样本工作区定义为由样本列表页和样本详情页组成的连续处理空间，使用户能够先完成样本筛选与预判，再围绕单个样本进入完整处理链，而不是把两个页面表达成彼此割裂的独立界面。

#### 场景:从样本列表进入样本详情
- **当** 用户在样本工作区浏览样本列表并选择某个样本
- **那么** 系统必须让该进入动作保留“当前位于样本工作区”的导航语义
- **那么** 系统必须让用户能够基于列表中的预判信息继续在详情页中完成处理，而不是重新理解页面上下文

### 需求:样本列表必须突出处理预判所需的关键信号
系统必须在样本列表中优先展示影响处理决策的关键信号，至少包括样本当前状态、是否存在未解决异常、是否存在待完成或失败的分析任务，以及结果录入是否仍待补充，禁止把这些信息完全隐藏到详情页后才可见。

#### 场景:在列表页快速识别高优先级样本
- **当** 用户在样本列表中批量查看待处理样本
- **那么** 系统必须允许其直接识别哪些样本存在风险、阻塞或待办强度较高
- **那么** 系统必须避免要求用户逐个进入详情页才能完成第一轮优先级判断

### 需求:样本详情必须遵循稳定的信息优先级
系统必须在样本详情页中按稳定层级组织信息，优先表达样本概览、当前风险或阻塞、推荐下一步，再展示结果、异常和分析任务等具体处理区块，禁止把高优先级引导淹没在页面下方的局部模块中。

#### 场景:首次进入样本详情页
- **当** 用户首次进入样本详情页
- **那么** 系统必须先表达当前样本所处阶段和需要优先关注的问题
- **那么** 系统必须在用户浏览具体处理区块前就提供明确的下一步理解路径
