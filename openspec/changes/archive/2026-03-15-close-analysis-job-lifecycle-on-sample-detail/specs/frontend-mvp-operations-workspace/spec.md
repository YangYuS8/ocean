## 新增需求

### 需求:样本详情中的分析任务必须提供状态后续引导
系统必须在样本详情页的分析任务区块中，根据分析任务的完成状态向用户提供最小后续处理引导，而不能只展示技术状态值。

#### 场景:查看成功任务的后续引导
- **当** 用户在样本详情页查看状态为 `succeeded` 的分析任务
- **那么** 系统必须展示结果摘要（若可用）
- **那么** 系统必须提示用户可以继续录入样本结果、记录异常或暂不处理

#### 场景:查看失败任务的后续引导
- **当** 用户在样本详情页查看状态为 `failed` 的分析任务
- **那么** 系统必须展示失败原因（若可用）
- **那么** 系统必须提示用户可以重新发起分析或记录异常

## 修改需求

### 需求:样本详情必须作为结果与后续动作的挂载中心
系统必须提供样本详情页，并在其中展示样本基本信息、结果列表、结果录入入口、样本级异常处理区块以及样本级分析任务区块，为样本处理链提供连续的 MVP 工作流；其中分析任务区块必须支持围绕当前样本查看生命周期状态、执行最小后续动作并获得状态后的处理提示。

#### 场景:查看样本详情
- **当** 用户进入样本详情页
- **那么** 系统必须调用现有样本详情接口展示样本基本信息与关联任务信息

#### 场景:查看样本结果列表
- **当** 用户在样本详情页查看结果区块
- **那么** 系统必须调用现有样本结果列表接口展示该样本的结果数据或明确空态

#### 场景:在样本详情页继续处理样本
- **当** 用户需要继续推进样本处理链
- **那么** 系统必须允许其在样本详情页直接发起结果录入、样本级异常处理和样本级分析任务，而不是要求跳转到独立结果、异常或分析任务模块
- **那么** 分析任务在成功或失败后必须继续把用户引导回结果录入、异常处理或重新发起分析等后续动作
