## 修改需求

### 需求:样本工作区必须提供真实样本列表与创建入口
系统必须将 `samples` 工作区从占位页面升级为真实业务页，允许用户查看样本列表并执行最小样本登记动作；同时，样本列表必须承担进入详情前的第一层工作台职责，让用户能够直接预判样本状态、风险和待办强度。

#### 场景:查看样本列表
- **当** 用户进入样本管理工作区
- **那么** 系统必须调用现有样本列表接口获取真实样本数据
- **那么** 系统必须展示至少样本编号、名称、类型、状态、来源任务和采集人信息

#### 场景:在样本列表预判处理优先级
- **当** 用户在样本工作区浏览多个样本
- **那么** 系统必须在列表中表达足以支持优先级判断的关键信号，至少包括未解决异常、待完成或失败的分析任务、以及结果录入是否仍待补充
- **那么** 系统必须允许用户从列表直接进入对应样本详情继续处理

#### 场景:登记样本
- **当** 用户在样本工作区执行新建样本操作
- **那么** 系统必须提供最小可用的样本登记表单
- **那么** 系统必须调用现有样本创建接口创建样本记录并给予明确反馈

### 需求:样本详情必须作为结果与后续动作的挂载中心
系统必须提供样本详情页，并在其中展示样本基本信息、工作台级处理摘要、结果列表、结果录入入口、样本级异常处理区块以及样本级分析任务区块，为样本处理链提供连续的 MVP 工作流；其中页面信息架构必须优先表达当前样本上下文、风险阻塞与推荐下一步，再进入各具体处理区块。

#### 场景:查看样本详情
- **当** 用户进入样本详情页
- **那么** 系统必须调用现有样本详情接口展示样本基本信息与关联任务信息

#### 场景:查看样本详情页工作台摘要
- **当** 用户进入样本详情页
- **那么** 系统必须在页面级表达当前样本状态、结果录入情况、异常情况和分析任务情况的最小摘要

#### 场景:查看样本详情页风险与推荐动作
- **当** 用户在样本详情页判断当前应优先处理的事项
- **那么** 系统必须在页面级提示未解决异常、执行中或待处理的分析任务等风险信息
- **那么** 系统必须根据结果录入、异常处理和分析任务状态向用户提供最小推荐下一步

#### 场景:查看样本结果列表
- **当** 用户在样本详情页查看结果区块
- **那么** 系统必须调用现有样本结果列表接口展示该样本的结果数据或明确空态

#### 场景:查看样本分析任务区块
- **当** 用户在样本详情页查看分析任务区块
- **那么** 系统必须围绕当前样本展示分析任务的生命周期状态，至少包括 `queued`、`running`、`succeeded`、`failed` 与 `cancelled`

#### 场景:在样本详情页继续处理样本
- **当** 用户需要继续推进样本处理链
- **那么** 系统必须允许其在样本详情页直接发起结果录入、样本级异常处理和样本级分析任务，而不是要求跳转到独立结果、异常或分析任务模块
- **那么** 分析任务在成功或失败后必须继续把用户引导回结果录入、异常处理或重新发起分析等后续动作
