## 为什么

当前样本工作区已经具备真实数据、结果录入、异常处理和分析任务能力，但页面的信息组织仍偏向“功能堆叠”，用户需要在列表、详情摘要和多个处理区块之间自行拼接上下文，才能判断当前位置、优先事项和下一步动作。这会放大样本处理中的认知负担，降低现场与实验协同效率。

现在推进这项变更，是为了在仍保持 MVP 范围的前提下，收拢样本工作区的信息架构，让样本列表到样本详情形成更稳定的导航语义、层级关系和处理路径，减少误判与来回跳转。

## 变更内容

- 重新定义样本工作区的信息架构，明确样本列表页、样本详情页和详情内各处理区块的层级分工。
- 强化样本列表中的关键信号与进入详情前的预判能力，让用户在进入样本详情前就能识别状态、风险和待办强度。
- 收敛样本详情页中的页面级摘要、区块排序和动作入口，使“当前态势 -> 风险阻塞 -> 推荐下一步 -> 具体处理区块”的阅读路径更清晰。
- 保持结果、异常和分析任务仍以内聚资源存在，不新增独立模块或后端编排接口，仅调整前端工作区表达与规范要求。

## 功能 (Capabilities)

### 新增功能
- `sample-workspace-information-architecture`: 定义样本工作区从列表到详情的层级组织、导航语义和页面内信息优先级，使用户能更快理解样本处理上下文。

### 修改功能
- `frontend-mvp-operations-workspace`: 调整样本工作区与样本详情页的工作台组织要求，使列表页和详情页形成更连续的处理路径。
- `sample-detail-workspace-guidance`: 将页面级摘要、风险提示和推荐下一步纳入更完整的信息架构约束，而不只停留在提示内容层。
- `sample-analysis-job-lifecycle`: 让分析任务在样本详情中的展示优先级和后续引导服从新的页面信息层级。
- `sample-exception-workflow`: 让异常状态在样本列表预判和详情页风险层中具备更一致的表达位置。
- `sample-result-entry-workflow`: 让结果录入状态参与列表摘要与详情页优先动作组织，减少用户在区块间搜索入口的成本。

## 影响

- 前端：`frontend/app/pages/samples/index.vue`、`frontend/app/pages/samples/[id].vue` 及其相关样本工作区组件结构、排序和文案
- 现有样本工作流：样本列表摘要、详情页工作台摘要、结果录入、异常处理、分析任务的入口组织与页面层级
- API 与基础设施：继续复用现有 Laravel API、Nuxt 页面与 Docker Compose/Nginx 部署，不要求新增后端聚合接口或基础设施调整
