## 新增需求

### 需求:巡检任务工作区必须提供真实任务列表
系统必须将 `inspections` 工作区从占位页面升级为真实业务页，允许用户查看巡检任务列表并进入任务详情。

#### 场景:查看巡检任务列表
- **当** 用户进入巡检任务工作区
- **那么** 系统必须调用现有巡检任务列表接口获取真实任务数据
- **那么** 系统必须展示至少任务编号、标题、状态、优先级、点位、计划时间和指派人信息

### 需求:巡检任务工作区必须支持最小状态推进动作
系统必须允许用户在巡检任务详情页执行最小状态推进动作，以支撑 MVP 巡检闭环。

#### 场景:开始巡检任务
- **当** 用户进入状态为 `assigned` 的任务详情页
- **那么** 系统必须提供“开始任务”动作入口
- **那么** 系统必须调用现有任务开始接口推进状态并在页面上刷新结果

#### 场景:提交巡检任务
- **当** 用户进入状态为 `in_progress` 的任务详情页
- **那么** 系统必须提供“提交任务”动作入口
- **那么** 系统必须调用现有任务提交接口推进状态并在页面上刷新结果

### 需求:样本工作区必须提供真实样本列表与创建入口
系统必须将 `samples` 工作区从占位页面升级为真实业务页，允许用户查看样本列表并执行最小样本登记动作。

#### 场景:查看样本列表
- **当** 用户进入样本管理工作区
- **那么** 系统必须调用现有样本列表接口获取真实样本数据
- **那么** 系统必须展示至少样本编号、名称、类型、状态、来源任务和采集人信息

#### 场景:登记样本
- **当** 用户在样本工作区执行新建样本操作
- **那么** 系统必须提供最小可用的样本登记表单
- **那么** 系统必须调用现有样本创建接口创建样本记录并给予明确反馈

### 需求:样本详情必须作为结果与后续动作的挂载中心
系统必须提供样本详情页，并在其中展示样本基本信息与结果列表，为后续异常和分析动作保留扩展入口。

#### 场景:查看样本详情
- **当** 用户进入样本详情页
- **那么** 系统必须调用现有样本详情接口展示样本基本信息与关联任务信息

#### 场景:查看样本结果列表
- **当** 用户在样本详情页查看结果区块
- **那么** 系统必须调用现有样本结果列表接口展示该样本的结果数据或明确空态

### 需求:核心工作流页面必须提供加载、空态和错误反馈
系统必须为巡检任务与样本工作区提供最小可用的页面状态反馈，禁止在接口请求期间或失败时直接退回占位内容。

#### 场景:接口加载中
- **当** 巡检任务或样本相关页面正在请求真实数据
- **那么** 系统必须展示明确的加载反馈

#### 场景:接口返回空数据
- **当** 列表或结果区块没有数据
- **那么** 系统必须展示与业务语境一致的空态提示

#### 场景:接口请求失败
- **当** 巡检任务或样本相关接口请求失败
- **那么** 系统必须向用户展示可理解的错误反馈

## 修改需求

### 需求:项目必须为后续业务模块预留标准页面入口
系统必须为样本管理、巡检任务、仪器监控、统计报表和系统设置提供标准页面入口；其中样本管理与巡检任务必须在当前 MVP 阶段升级为接入真实业务数据与动作的工作区页面，而不是继续停留在纯占位骨架。

#### 场景:进入模块页面
- **当** 用户点击任一样本管理或巡检任务导航入口
- **那么** 系统必须进入对应真实工作区页面并展示来自后端的业务数据与最小可用操作
- **那么** 其他尚未进入当前 MVP 范围的模块仍可以保留可继续扩展的页面壳或占位内容
