## 新增需求

### 需求:后端应用目录必须以 `backend/` 作为工作区边界
系统必须将 Laravel 后端应用承载在仓库根的 `backend/` 目录中，禁止继续以通用的 `src/` 目录名表达后端应用边界。

#### 场景:开发者查看仓库结构
- **当** 开发者浏览仓库根目录或阅读项目文档
- **那么** 其必须能够通过 `backend/` 明确识别 Laravel 后端应用的根目录

### 需求:PHP 运行时配置必须归属后端应用上下文
系统必须将 PHP-FPM 的 Dockerfile 与 PHP 配置文件放在 `backend/docker/php/` 下统一管理，禁止继续在仓库根保留独立的 `php/` 目录作为后端运行时配置入口。

#### 场景:开发者查找 PHP 镜像配置
- **当** 开发者需要调整 PHP 镜像构建、扩展安装或 `php.ini`
- **那么** 其必须能够在 `backend/docker/php/` 下找到对应文件

### 需求:PHP 镜像构建必须优先通过软件源优化解决超时问题
系统必须在迁移后的 PHP 镜像定义中保留当前 PHP 主版本，并通过 Debian 软件源优化提升 `apt` 安装稳定性，禁止仅因 Debian 默认源访问超时而无依据地下调 PHP 主版本。

#### 场景:构建 PHP 镜像时遇到 Debian 软件源超时
- **当** 开发环境构建 PHP 镜像且 `apt-get update` 受 Debian 默认源访问影响出现超时
- **那么** 系统必须通过 Debian 国内源替换或等价的可配置镜像源优化来解决构建稳定性问题
- **那么** 系统必须继续保持当前 PHP 主版本约定，除非另有明确的运行时兼容性证据

### 需求:容器编排必须使用新的后端目录约定
系统必须更新 Docker Compose 与 Nginx 的路径引用，使 PHP 服务构建、Laravel 文件挂载和 Nginx 到 `public/` 的访问全部基于 `backend/` 目录约定。

#### 场景:启动容器化开发环境
- **当** 开发者使用项目约定的 Docker Compose 工作流启动服务
- **那么** PHP 服务必须能够从新的后端目录构建镜像并挂载 Laravel 应用文件
- **那么** Nginx 必须能够通过新的挂载路径继续访问 Laravel `public/` 入口

### 需求:本次结构调整不得改变现有服务职责边界
系统必须在完成目录重命名与 PHP 运行时收拢后，继续保持 Nuxt、Nginx、MariaDB、Redis、Python 的既有职责边界，禁止在同一变更中顺手重组其他服务目录。

#### 场景:审查变更范围
- **当** 团队审查本次目录结构调整
- **那么** 变更必须聚焦于 `src/` 到 `backend/` 的迁移及 `php/` 到 `backend/docker/php/` 的收拢
- **那么** `frontend/`、`python/`、`nginx/` 等其他服务目录必须保持原有位置与职责不变
