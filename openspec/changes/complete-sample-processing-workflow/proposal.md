## 为什么

当前 MVP 已经完成巡检任务执行、样本登记和样本详情展示，但样本处理链仍停在“结果只读挂载点”，尚未真正支持实验结果录入。这使最初冻结的 MVP 主链 `巡检任务 -> 样本登记 -> 实验结果录入 -> 异常处理 -> 分析状态 -> 首页摘要` 还缺少中间关键一环，因此现在需要把样本结果录入接入前端真实工作流。

## 变更内容

- 在样本详情页接入最小可用的“新增结果”动作，允许用户围绕样本创建实验/检测结果。
- 为第一版结果录入限定少量 `result_type`，优先支持 `salinity_test` 与 `ph_test`，避免过早进入复杂结果建模。
- 使用带模板的 JSON 表单录入 `raw_value` 与可选的 `normalized_value`，在保持结构弹性的同时降低 MVP 录入门槛。
- 在成功创建结果后刷新结果列表，并按当前阶段的内聚状态推进规则将样本从 `registered` / `received` 推进到 `testing`。
- 保持现有 P0 API 契约、结果初始 `draft` 状态语义与显式传参身份策略不变，不在本次同步引入完整复核流、异常独立工作区或 Redis/Python 真闭环。

## 功能 (Capabilities)

### 新增功能
- `sample-result-entry-workflow`: 定义样本详情页内的结果录入动作、模板化 JSON 输入和样本处理状态推进规则。

### 修改功能
- `frontend-mvp-operations-workspace`: 将样本详情从“结果只读挂载中心”扩展为可录入实验结果的 MVP 处理工作区。
- `p0-api-foundation`: 补充样本结果录入后对样本状态推进的预期行为与前端最小录入约定。

## 影响

- `frontend/app/pages/samples/[id].vue` 及相关前端组件、表单校验和结果刷新逻辑。
- Laravel 现有 `POST /api/samples/{id}/results` 与样本详情/结果列表接口的前端接入方式。
- 样本状态在创建结果后的内聚推进逻辑，以及首页摘要中待处理样本的展示口径。
