## 上下文

当前样本详情页已经承担样本处理工作台角色，结果录入、异常处理和分析任务都集中挂载在 `samples/:id`。其中结果录入与异常处理已经具备显式动作和受控状态流转，但分析任务仍主要停留在“创建 queued 记录并查看列表”的水平。

现有状态文档已经冻结了 `analysis_jobs` 的目标状态机：`queued -> running -> succeeded/failed`，以及 `queued -> cancelled`。现有后端与前端也已经具备分析任务创建、列表和详情查询的基础，因此本次设计的重点不是引入新的运行时基础设施，而是在当前 Nuxt + Laravel + MariaDB 架构下，将分析任务收口为一个可解释、可继续操作的 MVP 闭环。

本次变更涉及前端样本详情工作台、PHP API 动作接口和分析任务服务层。Python/Redis 仍然是未来真实异步执行链的长期边界，但本次不要求它们立即成为状态推进的唯一来源。

## 目标 / 非目标

**目标：**
- 为分析任务补齐最小生命周期动作，遵循现有动作型接口与严格状态校验模式。
- 在样本详情页上让分析任务成功/失败后具备清晰的下一步引导，而不仅仅是状态展示。
- 明确“重新发起分析”的产品与数据语义：失败后基于原任务上下文创建新任务记录，保留原任务失败历史。
- 保持分析任务作为“后台分析过程”资源，与样本结果和异常资源分离。

**非目标：**
- 不在本次接入完整 Redis/Python 自动消费和回写链路。
- 不将分析任务成功自动写回样本结果，也不自动改变样本主状态。
- 不将分析任务失败自动转换为异常记录。
- 不引入复杂参数配置系统、独立分析模块或细粒度权限体系。
- 不在本次强制增加重试父子链字段或复杂任务编排模型。

## 决策

### 1. 分析任务继续采用动作型接口，而不是通用状态更新

沿用 `inspection_tasks` 与 `exceptions` 的现有风格，分析任务生命周期通过显式动作推进，而不是开放一个可任意修改 `status` 的通用更新接口。这样可以保持状态机边界稳定，并减少前端误用空间。

备选方案：
- 通用 `PATCH /api/analysis-jobs/{id}` 更新状态：实现看似更短，但会弱化状态约束，不符合当前仓库的动作型 API 风格。

### 2. 成功/失败后的引导留在样本详情页，而不是自动联动业务资源

分析任务表达的是后台分析过程，而不是最终业务结果。成功后应提供摘要和下一步入口，引导用户去录入结果、记录异常或继续观察；失败后应提供失败原因和重新发起/记录异常的入口建议，但不自动转成样本结果或异常。

备选方案：
- 成功自动生成样本结果：会混淆“过程资源”和“业务结果资源”的职责边界。
- 失败自动生成异常：会把技术执行失败和业务异常混在一起。

### 3. 重新发起分析采用“新建任务记录”语义

失败后的重新发起不是把原任务从 `failed` 重置回 `queued`，而是基于原任务上下文创建一条新的 `analysis_jobs` 记录。原任务保留失败历史，新任务以新的 `queued_at` 和生命周期进入列表。这与当前状态文档一致，也更符合 `analysis_jobs` 作为“一次执行尝试”的资源语义。

备选方案：
- 原地重试：会污染单条任务记录的历史语义，并等价于给状态机新增 `failed -> queued` 的回退边。
- 建立显式父子链字段：长期可能有价值，但对当前 MVP 来说会增加模型与展示复杂度，因此暂不强制纳入。

### 4. 本次允许用最小受控方式推进状态，为未来真异步预留接口边界

考虑到 Redis/Python 真异步链路尚未成为当前 MVP 主路径，本次设计允许在 PHP API 层提供受控状态推进动作，使页面上的分析任务区块先形成工作闭环。后续接入真实 worker 时，可以复用同一状态语义，并逐步收缩这些动作的可见性或调用来源。

备选方案：
- 等到 Python/Redis 完整落地后再做状态推进：会让分析任务区块长期停留在“只会 queued”的半成品状态。

## 风险 / 权衡

- [风险] 当前阶段允许通过 API 受控推进分析任务状态，可能与未来“仅后台可推进”的最终模型存在偏差。 → 缓解：在规范中明确这些动作服务于当前 MVP 闭环，后续真实异步接入时仅调整调用来源，不改变状态语义。
- [风险] 成功后只给摘要和建议动作，可能让部分用户期待“自动生成业务结果”。 → 缓解：在设计和页面文案中明确分析任务是过程资源，结果录入仍是独立业务动作。
- [风险] 失败后采用“新建任务记录”的重试语义，若列表变长可能影响可读性。 → 缓解：当前样本详情页已经按样本上下文过滤列表，后续若出现频繁重试场景，再考虑显式父子链或分组展示。
- [风险] 移动端样本详情页加入更多分析状态和动作后，区块密度可能上升。 → 缓解：继续沿用现有分块卡片布局，把建议动作限制在最少集合，避免在一版内引入复杂控制面板。
