## 为什么

当前样本详情页已经可以围绕样本发起分析任务并查看任务列表，但分析任务仍停留在“创建 queued 记录并展示状态”的阶段，尚未形成可解释、可继续处理的最小闭环。这使分析任务区块更像登记板，而不是样本处理工作台中的有效过程区块。

现在推进这项变更，是为了在不提前引入完整 Redis/Python 自动消费链的前提下，先把分析任务的生命周期、失败后的重新发起语义以及样本详情页上的下一步引导收口到 MVP 可演示、可追踪、可扩展的状态。

## 变更内容

- 为样本级分析任务补齐最小生命周期推进能力，覆盖 `queued`、`running`、`succeeded`、`failed`、`cancelled` 的受控流转。
- 在样本详情页强化分析任务区块，让成功和失败状态不仅可见，还能向用户表达下一步建议。
- 明确失败后的“重新发起分析”语义：采用基于原上下文新建任务记录的方式保留失败历史，而不是复活原任务。
- 保持分析任务与业务结果、业务异常分离；本次不引入自动将分析结果写回样本结果，也不自动将任务失败转成异常。
- 保持当前 MVP 范围收敛：不接入完整 Python/Redis 真异步执行链，不扩展复杂参数系统，不新增独立分析模块。

## 功能 (Capabilities)

### 新增功能

- `sample-analysis-job-lifecycle`: 定义样本级分析任务的最小生命周期动作、失败后重新发起语义，以及样本详情页上的状态后续引导。

### 修改功能

- `frontend-mvp-operations-workspace`: 将样本详情页中的分析任务区块从“发起 + 查看”扩展为“状态可解释 + 可继续操作”的工作流区块。
- `p0-api-foundation`: 扩展分析任务 API 要求，使其支持最小状态推进与失败后基于原上下文重新发起的新任务记录。

## 影响

- 前端：`frontend/app/pages/samples/[id].vue` 的分析任务区块交互、状态展示和下一步引导。
- 后端：`backend/routes/api.php`、分析任务相关 request/controller/service 及分析任务状态校验逻辑。
- 数据与接口：`analysis_jobs` 资源的动作型 API、状态流转口径、失败后重新发起语义。
- 基础设施：不要求修改当前 Nuxt、Nginx、Docker Compose、MariaDB 或 Redis 基础部署；Redis/Python 仍保留为后续真实异步接入边界。
