## 为什么

当前代码实现和 OpenSpec 主规范已经把分析任务推进到了“最小生命周期闭环”阶段，但部分项目文档仍停留在“提交 + 状态查询”为主的旧基线。这会让后续围绕样本详情工作台、Redis/Python 异步执行链和 API 边界的讨论失去统一参照。

现在更新文档，是为了把已经落地的 MVP 现实回写到关键设计文档中，降低产品讨论、实现规划和回归验证时的认知漂移风险。

## 变更内容

- 校准与分析任务相关的 MVP 核心文档，使其反映当前已落地的生命周期动作、失败后重新发起语义和样本详情页中的后续引导能力。
- 对齐 API 范围、字段草案、状态流转说明和实现/验证说明，使它们与当前 Laravel + Nuxt 实现和 OpenSpec 主规范保持一致。
- 保持文档更新范围收敛：本次只回写已经实现并归档的能力，不借机扩张到新的产品功能或 Redis/Python 真异步执行链设计。

## 功能 (Capabilities)

### 新增功能

- `mvp-doc-baseline-sync`: 定义 MVP 关键设计文档与当前主规范/实现状态之间的同步与校准要求。

### 修改功能

- `p0-api-foundation`: 将分析任务 API 的文档化基线从“创建 + 查询”更新为“创建 + 查询 + 最小状态推进 + 失败后重新发起”。
- `sample-analysis-job-lifecycle`: 将当前分析任务生命周期主规范落实为项目级文档中的稳定叙述基线。

## 影响

- 文档：`docs/2.4-MVP-API-范围冻结稿.md`、`docs/2.6-P0-API-字段草案.md`、`docs/2.7-P0-状态流转草案.md`、`docs/2.9-P0-实现与验证说明.md`
- 规范：新增一个与文档校准相关的主规范能力，并通过增量规范明确哪些现有能力需要被文档基线回写
- 实现代码与基础设施：本次不要求修改 Nuxt、Nginx、Docker Compose、MariaDB、Redis 或应用代码
