## 新增需求

### 需求:样本详情必须表达当前处理态势与推荐动作
系统必须让样本详情页在页面级别表达当前样本所处的处理态势、风险提示和推荐动作，而不能只把结果、异常和分析任务作为彼此独立的并列区块展示。

#### 场景:查看样本详情工作台摘要
- **当** 用户进入样本详情页
- **那么** 系统必须在页面关键位置展示当前状态摘要、阻塞或风险提示以及推荐下一步

#### 场景:查看样本详情推荐动作
- **当** 当前样本存在多个可继续操作的入口
- **那么** 系统必须对推荐动作进行最小优先级表达，而不是把所有动作平铺为同等优先级

## 修改需求

### 需求:样本详情必须作为结果与后续动作的挂载中心
系统必须提供样本详情页，并在其中展示样本基本信息、结果列表、结果录入入口、样本级异常处理区块以及样本级分析任务区块，为样本处理链提供连续的 MVP 工作流；其中页面级工作台摘要必须帮助用户理解当前样本的整体处理态势、推荐下一步与主要风险。

#### 场景:查看样本详情
- **当** 用户进入样本详情页
- **那么** 系统必须调用现有样本详情接口展示样本基本信息与关联任务信息

#### 场景:查看样本结果列表
- **当** 用户在样本详情页查看结果区块
- **那么** 系统必须调用现有样本结果列表接口展示该样本的结果数据或明确空态

#### 场景:查看样本分析任务区块
- **当** 用户在样本详情页查看分析任务区块
- **那么** 系统必须围绕当前样本展示分析任务的生命周期状态，至少包括 `queued`、`running`、`succeeded`、`failed` 与 `cancelled`

#### 场景:在样本详情页继续处理样本
- **当** 用户需要继续推进样本处理链
- **那么** 系统必须允许其在样本详情页直接发起结果录入、样本级异常处理和样本级分析任务，而不是要求跳转到独立结果、异常或分析任务模块
- **那么** 页面级工作台摘要必须帮助用户优先识别更适合当下执行的动作
