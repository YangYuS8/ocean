## 上下文

当前样本工作区已经覆盖真实样本列表、样本详情、结果录入、异常处理和分析任务，但信息架构仍主要随着功能增量自然堆叠。列表页更像数据表，详情页更像能力容器，用户要靠自己在多个区块间来回比对，才能判断样本是否需要立即处理、应该优先处理什么、以及哪些信息只是补充上下文。

这类问题本质上属于前端信息组织，而不是后端能力缺失。现有 Laravel API 已能提供样本列表、样本详情、结果、异常和分析任务所需数据，Nuxt 前端也已经具备单页工作台能力。本次设计应优先通过页面层级、区块排序、摘要信号和动作优先级来改善认知路径，而不是引入新的聚合接口、规则引擎或独立模块。

## 目标 / 非目标

**目标：**
- 让样本列表页承担“筛选与预判”角色，让用户进入详情前即可识别状态、风险和待办强度。
- 让样本详情页形成稳定的阅读顺序：上下文概览、风险阻塞、推荐下一步、具体处理区块。
- 让结果、异常和分析任务三个区块在同一页面中遵守一致的信息优先级，减少重复提示和入口分散。
- 保持桌面端与移动端都能沿着相同信息层级完成样本处理，不因布局折叠打乱优先顺序。

**非目标：**
- 不新增后端聚合 summary API、自动决策服务或新的 MariaDB 数据模型。
- 不将结果、异常或分析任务拆分成独立路由工作区。
- 不改变现有 Laravel、Nuxt、Nginx、Docker Compose 或 Redis 的部署拓扑。
- 不在本次变更中重做样本状态机本身，只调整它在工作区中的表达方式。

## 决策

### 1. 采用“两层工作区”结构，而不是继续把样本列表和详情视为独立页面

样本列表页负责批量浏览、快速筛选和进入处理，样本详情页负责围绕单个样本执行完整处理链。规范需要明确这两个页面是同一工作区中的前后层级，而不是两个彼此独立的界面，这样列表中的状态摘要、风险信号和待办强度才能自然映射到详情页中的摘要与区块操作。

备选方案：
- 只优化样本详情页，不调整列表页语义：实现更快，但无法解决用户进入详情前缺少预判信息的问题。

### 2. 使用前端派生摘要组织信息优先级，而不是新增后端聚合接口

样本列表和样本详情已具备足够字段来生成第一版信息架构：样本状态、结果是否存在、是否有 open 异常、分析任务是否 queued/running/failed。前端应基于现有接口派生统一的摘要信号，并将其投射到列表卡片/表格列、详情摘要和推荐动作中，避免为了页面组织再引入新的 PHP 聚合层。

备选方案：
- 新增后端 workspace summary 接口：长期可能提高一致性，但当前规则简单，增加接口会抬高 MVP 成本。

### 3. 详情页按“概览优先、动作次之、明细最后”的固定顺序组织

样本详情页需要先回答“这是什么样本、当前到哪一步、是否有风险、建议先做什么”，再进入结果、异常和分析任务的具体区块。规范应要求页面级摘要与风险提示位于处理区块之前，且主动作入口与推荐下一步保持邻近，避免用户必须滚动到页面下半段才能找到关键动作。

备选方案：
- 将每个区块各自放置动作入口和局部提示：局部实现简单，但整体决策路径仍然分散。

### 4. 用稳定区块优先级消解多模块竞争注意力的问题

异常、分析任务和结果录入都可能声称自己是“下一步”。为了避免页面出现多个同等强度的主提示，规范需要固定优先级：风险/阻塞高于推荐下一步，推荐下一步高于区块明细；区块内部继续保留资源语义，但不得重复声明与页面级摘要冲突的主优先级。这样可以让样本工作区保持单一主线，同时保留专业资源边界。

备选方案：
- 允许各区块独立声明自己的主要提示：会造成文案竞争，削弱页面级信息架构。

### 5. 响应式布局保持相同信息顺序，而不是移动端重新定义阅读逻辑

移动端仍需支持现场巡检和便携设备查看。页面可以在视觉上从多列收敛为单列，但摘要、风险、推荐动作和处理区块的逻辑顺序必须保持一致，避免因为折叠或抽屉式布局导致移动端用户比桌面端更难找到主动作。

备选方案：
- 为移动端单独设计另一套区块顺序：短期可做更紧凑，但会增加认知切换和维护成本。

## 风险 / 权衡

- [风险] 仅依赖前端派生规则可能在边缘状态下出现摘要与用户预期不完全一致。 -> 缓解：先把规则限定为结果、异常、分析任务三类高价值信号，并在规范中避免过度自动判断。
- [风险] 列表页加入更多摘要后可能提高信息密度。 -> 缓解：要求列表只展示进入详情前最有价值的状态、风险和待办信号，不复制详情全部内容。
- [风险] 页面级主动作与区块内动作并存时，可能出现入口重复。 -> 缓解：规范要求页面级推荐动作作为优先入口，区块内入口保留但不重复竞争主层级。
- [风险] 移动端在单列布局下容易拉长页面。 -> 缓解：通过固定层级、折叠低优先级说明和保留关键摘要在首屏附近控制滚动成本。
