## 2.4 MVP API 范围冻结稿

### 2.4.1 目的

- 本稿用于冻结当前阶段 `MVP API` 范围，避免在数据表设计、接口定义和前端联调过程中持续扩张需求。
- 本稿面向当前项目的第一阶段落地，服务于 `Nuxt 工作台 + PHP 业务接口 + MariaDB + Redis/Python 轻量异步接入` 的现实约束。
- 本稿不定义最终平台能力，仅定义当前阶段必须与可选的 API 边界。

### 2.4.2 范围原则

- 当前阶段 API 只围绕以下最小业务闭环设计：
  - 巡检任务
  - 样本登记
  - 实验结果录入
  - 异常处理
  - 分析任务状态
  - 首页摘要
- 凡是不直接服务于上述闭环的接口，不纳入当前阶段 MVP。
- 当前阶段优先保证“可操作、可追踪、可扩展”，不追求一次性覆盖完整行业平台能力。

### 2.4.3 P0 API（当前阶段必须实现）

这些接口属于第一阶段最小可交付集合。若缺失，将直接影响工作台从占位态进入真实业务联调。

#### 1. Dashboard

- `GET /api/dashboard/summary`

用途：

- 提供首页关键摘要数据。
- 当前建议至少包含：
  - 待处理样本数
  - 今日巡检任务数
  - 未处理异常数
  - 分析任务队列数

#### 2. Inspection Tasks

- `GET /api/inspection-tasks`
- `GET /api/inspection-tasks/{id}`
- `POST /api/inspection-tasks/{id}/start`
- `POST /api/inspection-tasks/{id}/submit`

用途：

- 支持巡检任务列表展示、任务详情查看、开始执行、提交结果。
- 当前阶段不强求任务创建端在前台完整开放，但必须支持任务执行闭环。

#### 3. Samples

- `GET /api/samples`
- `POST /api/samples`
- `GET /api/samples/{id}`

用途：

- 支持样本登记、样本查询与样本详情查看。
- 样本为系统长期主对象，是后续结果、异常与分析任务的关联中心。

#### 4. Sample Results

- `GET /api/samples/{id}/results`
- `POST /api/samples/{id}/results`

用途：

- 支持围绕样本录入实验或检测结果。
- 当前阶段只要求能录、能查，不强求完整复核流。

#### 5. Exceptions

- `GET /api/exceptions`
- `POST /api/exceptions`
- `POST /api/exceptions/{id}/resolve`

用途：

- 支持异常记录、异常列表查看、异常处理闭环。
- 异常作为独立资源存在，不仅是任务或样本上的一个状态标记。

#### 6. Analysis Jobs

- `GET /api/analysis-jobs`
- `POST /api/analysis-jobs`
- `GET /api/analysis-jobs/{id}`

用途：

- 支持发起异步分析任务并查看状态。
- 当前阶段分析任务以“提交 + 状态查询”为主，不要求复杂结果体系。

### 2.4.4 P1 API（建议保留，但不阻塞第一阶段闭环）

这些接口建议在 P0 稳定后补充，用于提升工作台可用性与业务顺滑度。

#### 1. Dashboard

- `GET /api/dashboard/activity-feed`

#### 2. Inspection Tasks

- `POST /api/inspection-tasks`
- `POST /api/inspection-tasks/{id}/complete`

#### 3. Samples

- `PATCH /api/samples/{id}`
- `POST /api/samples/{id}/receive`
- `POST /api/samples/{id}/attachments`

#### 4. Sample Results

- `GET /api/sample-results/{id}`
- `POST /api/sample-results/{id}/submit-review`
- `POST /api/sample-results/{id}/approve`
- `POST /api/sample-results/{id}/reject`

#### 5. Exceptions

- `GET /api/exceptions/{id}`
- `POST /api/exceptions/{id}/acknowledge`

#### 6. Analysis Jobs

- `POST /api/analysis-jobs/{id}/retry`

#### 7. Reports

- `GET /api/reports/overview`

### 2.4.5 明确不纳入当前 MVP 的 API 范围（Out of Scope）

以下接口方向不进入当前阶段冻结范围：

- 离线同步与冲突合并
- GPS/北斗围栏与轨迹校验
- 视频采集、流媒体播放、大文件编排
- 复杂设备实时监控与时序数据接口
- 模型版本管理、灰度发布、回滚
- 多格式专业报告导出编排
- 外部国家平台或第三方服务集成
- 复杂组织架构、细粒度数据权限后台
- 全量审计流水线专属平台 API

```text
Out of Scope
────────────────────────
offline sync
geo fence
video pipeline
device realtime telemetry
model management
advanced reporting
external integrations
heavy admin platform
```

### 2.4.6 当前阶段 API 设计约束

- 首页类页面优先使用聚合接口，不要求前端自行拼装多个资源接口。
- 状态流转优先使用显式动作接口，如 `start`、`submit`、`resolve`，避免前端任意修改状态字段。
- 样本与实验结果分离建模，不混用一个资源。
- 异常作为独立资源统一建模，以便后续跨任务、样本、结果扩展。
- 分析任务与业务结果分离，`analysis_jobs` 表示后台异步过程，而不是最终业务结果本身。

### 2.4.7 冻结结论

当前阶段 API 冻结结论如下：

- 以 `dashboard / inspection-tasks / samples / sample-results / exceptions / analysis-jobs` 为 MVP 主域。
- 以 `P0` 为第一实现目标，优先支撑真实业务工作台联调。
- `P1` 可进入后续迭代，不作为当前数据表和接口设计的阻塞条件。
- `Out of Scope` 内容不得在当前阶段以“顺手一起做”的方式重新进入范围。
