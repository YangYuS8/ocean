## 上下文

当前系统已经围绕 `samples/:id` 建立了结果录入、异常处理和 `analysis_jobs` 过程资源，但样本还没有清晰的图像输入契约，Python 侧也尚未形成真正可消费的模型推理闭环。与此同时，外部 YOLO 模型已经具备基本可用性，适合作为样本工作台上的辅助分析能力来验证产品价值。

本次设计刻意保持 MVP 收敛：不把它扩展成完整图片管理系统，也不把模型输出直接升级为正式业务结果，而是先建立“单主图 + 手动触发 + 参考建议”的最小闭环。现有部署保持不变：Nginx 代理 Nuxt 与 Laravel，MariaDB 落业务数据，Redis 作为异步边界，Python 负责后续 YOLO 推理执行。

## 目标 / 非目标

**目标：**
- 为每个样本建立唯一主图语义，并把主图作为当前 YOLO 检测的唯一输入对象。
- 让用户在 `samples/:id` 上手动触发 YOLO 检测，并获得一份仅供人工参考的自动检测建议。
- 继续复用 `analysis_jobs` 作为检测过程资源，明确“过程状态”和“建议消费层”分离。
- 将 YOLO 输出收敛为“摘要 + 轻量结构化建议”，为后续演化保留接口但不引入完整视觉平台。

**非目标：**
- 不在本次变更中实现多图管理、图片相册、图片版本管理或完整媒体系统。
- 不将 YOLO 输出直接写成正式 `sample_results`，也不自动驱动异常、状态流转或业务决策。
- 不在本次变更中展开多模型治理、模型训练平台或完整异步平台重构。

## 决策

### 1. 样本在 MVP 阶段只拥有一张主图
- 选择：把主图视为 `sample` 的当前图像输入，而不是先做完整多图片管理；由 Laravel 持久化主图引用并在业务上保证每个样本只有一张主图。
- 原因：当前需要验证的是模型建议在样本工作台里的价值，而不是图片管理系统本身。单主图能让输入语义、页面心智和时效判断都保持清晰。
- 替代方案：一开始就支持多图与主图切换。该方案会显著扩大范围，并把讨论重心从工作台建议拉回图片管理。

### 2. YOLO 建议与正式业务结果严格分层
- 选择：YOLO 输出只形成“自动检测建议”，由前端展示为工作台辅助信息；正式结果仍由人工在现有结果录入流程中确认。
- 原因：这与当前 `analysis_jobs` 是过程资源、`sample_results` 是业务结果的分层一致，也能避免模型误检直接污染业务真值。
- 替代方案：将 YOLO 输出直接写入正式结果或自动修改样本状态。该方案会过早放大模型责任边界。

### 3. 手动触发检测，但底层继续使用 analysis job 语义
- 选择：用户在 `samples/:id` 上点击“运行自动检测”时创建新的 YOLO `analysis_job`；首次运行、重新检测、失败重试都表现为新的检测尝试。
- 原因：这与现有 `analysis_jobs` 生命周期和“retry 创建新记录”的语义一致，也能保留完整历史。
- 替代方案：复活旧 job 或直接在样本记录上覆写建议。前者破坏过程追溯，后者会混淆建议与主数据。

### 4. 页面同时保留“建议消费层”和“分析任务记录层”
- 选择：`samples/:id` 新增“自动检测建议”卡片，用于展示当前主图的最新建议；原有 `analysis_jobs` 区块继续保留，作为历史过程记录与失败追踪区。
- 原因：用户需要先看到“模型看到了什么”，而不是直接消费技术状态；同时当前系统仍需要保留 job 级可追溯性。
- 替代方案：只在 `analysis_jobs` 列表里显示 YOLO 结果。该方案在产品层可读性弱，更像后台日志。

### 5. 建议展示采用“摘要 + 轻量结构化建议”
- 选择：主页面优先展示状态、建议摘要、是否有发现、简单置信度概览和“仅供参考”文案；详情层可消费轻量结构化建议，但不要求完整 bbox 平台化。
- 原因：这能兼顾工作台可读性和后续演化空间，避免把 MVP 推成完整可视化标注产品。
- 替代方案：只存一句摘要文本或直接保存完整原始检测输出。前者会限制后续演化，后者会显著放大实现面。

## 风险 / 权衡

- [建议与当前主图脱节] → 将“当前有效建议”定义为基于当前主图生成的最新成功检测；主图一旦替换，旧建议只保留历史，不再作为当前建议展示。
- [同一主图被反复重复触发] → 限制同一主图在同一时刻只存在一个进行中的 YOLO 检测 job。
- [移动端展示检测细节过载] → 默认卡片只展示摘要和关键操作，将详情与预览保留在二级层。
- [算法建议被误认为最终结论] → 在界面与接口语义中明确“仅供人工参考”，不自动写入正式结果。

## Migration Plan

1. 定义并落地主图输入契约，使样本详情能读取和更新当前主图。
2. 为 YOLO 检测定义面向当前主图的任务参数与结果结构，继续通过 `analysis_jobs` 承载生命周期。
3. 在 Python 侧把 YOLO 输出转换为“摘要 + 轻量结构化建议”，并写回可被 Laravel 消费的结果。
4. 在 Nuxt 样本详情页增加主图区和自动检测建议区，保留原有分析任务记录区。
5. 验证主图替换、建议过期、失败重试和空建议（无检测目标）等关键路径。

## Open Questions

- 主图引用在 MVP 中更适合直接挂在 `sample`，还是先设计成可演化的图片关联资源。
- 轻量结构化建议是否只保存计数与摘要，还是保留一小部分可选预览数据。
- Redis 是否在首个实现中就接入，还是先允许一个更窄的 Python 执行路径验证模型价值。

## Deferred Enhancements

- 检测预览图：本轮评估后继续延后，当前先用“摘要 + 轻量结构化建议”验证模型价值，不把页面推成可视化标注面板。
- 人工采纳记录：本轮继续延后，先保持“建议”与“正式结果”分层，后续再考虑记录采纳/忽略行为用于效果分析。
- 候选结果转换：本轮继续延后，YOLO 输出仍只作为工作台参考建议，不自动生成候选 `sample_results`。
