## 为什么

当前前端工作台已经具备基础页面结构，但 PHP 后端仍缺少与样本管理、巡检任务、异常处理和分析任务相关的可用 API 与数据库基础，导致前端仍停留在占位数据阶段。现在推进 P0 API 与 MariaDB 数据结构实现，可以先打通“任务 -> 样本 -> 结果 -> 异常 -> 分析任务 -> 首页摘要”的最小业务闭环，为后续真实联调和逐步扩展提供稳定基础。

## 变更内容

- 在现有 PHP 后端中实现 P0 业务 API，包括首页摘要、巡检任务、样本、样本结果、异常记录和分析任务接口。
- 按已确认的 P0 数据模型落地 MariaDB 数据表、索引、外键和初始化角色数据。
- 保持现有 Nuxt 4、Nginx、Docker Compose、MariaDB 与 Redis 运行方式不变，在当前部署模型内完成渐进扩展。
- 优先支持 MVP 联调所需的显式传参、状态流转和 JSON 结果载荷，不同步引入超出 P0 范围的离线、复杂权限、模型管理或高级报表能力。

## 功能 (Capabilities)

### 新增功能
- `p0-api-foundation`: 提供 P0 阶段所需的 PHP API、MariaDB 数据表和基础初始化数据，支撑工作台从占位数据进入真实业务联调。

## 影响

- `src/` 下的 PHP 后端代码结构、路由和接口实现。
- MariaDB 数据表、索引、初始化数据与后续迁移脚本。
- Nuxt 前端与 PHP `/api/` 的联调方式。
- Redis 与 Python 的异步分析任务接入边界，但不改变其现有部署模型。
