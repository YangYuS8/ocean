# sample-exception-workflow 规范

## 目的
定义样本详情页内的最小异常处理工作流，使样本在结果录入之后能够继续记录、查看和解决异常，补上 MVP 主链中的异常处理环节。

## 需求
### 需求:样本详情必须提供样本级异常处理区块
系统必须在样本详情页内提供异常处理区块，允许用户围绕当前样本查看异常列表、记录异常和解决异常，而不能要求其跳转到独立异常模块才能完成当前样本处理链。

#### 场景:查看样本异常区块
- **当** 用户进入样本详情页
- **那么** 系统必须展示当前样本的异常处理区块

### 需求:异常第一版必须仅挂载到样本资源
系统必须将第一版异常记录的资源范围收敛为 `sample`，禁止在当前 MVP 阶段同时开放 `inspection_task` 与 `sample_result` 级异常创建作为主交互方式。

#### 场景:记录样本异常
- **当** 用户在样本详情页创建异常
- **那么** 系统必须以 `resource_type=sample` 和当前样本 ID 创建异常记录

### 需求:异常录入必须使用极小分类集合
系统必须将第一版异常分类收敛为少量固定选项，以降低录入门槛并保持后续可扩展性。

#### 场景:选择异常分类
- **当** 用户填写异常录入表单
- **那么** 系统必须至少提供 `sample_quality`、`record_mismatch` 与 `handling_issue` 三个分类选项

### 需求:异常工作流第一版必须支持记录与解决闭环
系统必须在样本详情页内同时支持异常创建与异常解决，以形成最小可用的异常处理闭环。

#### 场景:创建异常
- **当** 用户提交合法的异常录入表单
- **那么** 系统必须调用现有异常创建接口创建异常记录
- **那么** 系统必须将异常初始状态设置为 `open`
- **那么** 系统必须刷新当前样本的异常列表并展示成功反馈

#### 场景:解决异常
- **当** 用户在样本详情页对 `open` 状态的异常执行解决动作
- **那么** 系统必须调用现有异常解决接口将异常推进到 `resolved`
- **那么** 系统必须刷新当前样本的异常列表并展示成功反馈

### 需求:异常状态不得在第一版自动改动样本状态
系统必须在当前 MVP 阶段将异常状态与样本状态解耦，禁止因异常创建或解决而自动推进或回退样本状态。

#### 场景:创建异常后查看样本状态
- **当** 用户为当前样本创建异常记录
- **那么** 系统不得仅因异常创建而自动修改样本状态

#### 场景:解决异常后查看样本状态
- **当** 用户解决当前样本上的异常记录
- **那么** 系统不得仅因异常解决而自动修改样本状态
