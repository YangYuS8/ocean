## 为什么

当前 `samples/:id` 已经承载样本结果录入、异常处理和分析任务生命周期，但页面仍主要按并列区块展示能力，尚未充分回答“这个样本现在卡在哪”“我下一步该做什么”。这会让用户在样本处理台中看到很多动作，却仍需要自己判断优先级和阻塞点。

现在推进这项变更，是为了把样本详情页从“能力挂载中心”进一步收口为“工作台引导中心”，让 MVP 在不引入新业务模块的前提下，更清楚地表达当前阶段、风险阻塞和推荐下一步。

## 变更内容

- 在样本详情页增加更明确的工作台引导层，围绕当前样本状态、异常、结果和分析任务形成可读的“当前处理态势”。
- 增强样本详情页中的下一步建议逻辑，使用户能快速判断应优先录入结果、处理异常、重新发起分析或暂不处理。
- 保持当前样本详情页作为处理中心，不新建独立工作流模块，不改变分析任务、异常或结果的资源边界。
- 优先使用已有数据和状态组合出更强的引导信息，而不是新增复杂后端编排或自动决策系统。

## 功能 (Capabilities)

### 新增功能

- `sample-detail-workspace-guidance`: 定义样本详情页中的工作台摘要、阻塞提示与下一步建议要求，使其成为更明确的处理引导界面。

### 修改功能

- `frontend-mvp-operations-workspace`: 将样本详情页从“结果与后续动作挂载中心”进一步收口为“当前处理状态 + 推荐下一步”的工作台。
- `sample-analysis-job-lifecycle`: 让分析任务在样本详情页中的成功/失败后续引导与页面级工作台摘要形成一致的推荐语义。
- `sample-exception-workflow`: 让样本详情页中的异常状态参与工作台级阻塞提示与推荐下一步判断。
- `sample-result-entry-workflow`: 让结果录入状态参与工作台级推荐下一步判断与处理优先级表达。

## 影响

- 前端：`frontend/app/pages/samples/[id].vue` 的页面结构、摘要卡片、推荐动作和空态/提示文案
- 现有前端工作流能力：样本结果、异常处理、分析任务在同一页面内的组织与引导方式
- API 与基础设施：优先复用现有 Laravel API 与数据结构；本次不要求新增 Redis、MariaDB、Docker Compose 或 Nginx 基础设施改动
