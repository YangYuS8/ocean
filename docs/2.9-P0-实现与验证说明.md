## 2.9 P0 实现与验证说明

本稿记录当前阶段 P0 后端实现的落地方式、最小验证路径和后续扩展注意点。

### 2.9.1 已落地的实现范围

- 在 `src/` 中建立了轻量 PHP API 骨架、统一 JSON 响应结构、基础请求解析和数据库访问层。
- 提供了 P0 所需的 `/api/` 路由：
  - `GET /api/dashboard/summary`
  - `GET /api/inspection-tasks`
  - `GET /api/inspection-tasks/{id}`
  - `POST /api/inspection-tasks/{id}/start`
  - `POST /api/inspection-tasks/{id}/submit`
  - `GET /api/samples`
  - `POST /api/samples`
  - `GET /api/samples/{id}`
  - `GET /api/samples/{id}/results`
  - `POST /api/samples/{id}/results`
  - `GET /api/exceptions`
  - `POST /api/exceptions`
  - `POST /api/exceptions/{id}/resolve`
  - `GET /api/analysis-jobs`
  - `POST /api/analysis-jobs`
  - `GET /api/analysis-jobs/{id}`
- 提供了 MariaDB 建表脚本与初始化数据脚本：
  - `src/database/schema.sql`
  - `src/database/seed.sql`
  - `src/scripts/migrate.php`
  - `src/scripts/seed.php`

### 2.9.2 最小执行命令

在当前 Docker Compose 环境中，可通过以下命令完成 P0 数据库初始化：

```bash
docker compose up -d db php nginx redis
docker compose exec php php /var/www/html/scripts/migrate.php
docker compose exec php php /var/www/html/scripts/seed.php
```

### 2.9.3 最小接口验证路径

以下命令覆盖了 P0 的关键业务闭环：

**1. 查询首页摘要**

```bash
curl -s http://localhost:8080/api/dashboard/summary
```

**2. 查询巡检任务并推进状态**

```bash
curl -s http://localhost:8080/api/inspection-tasks
curl -s -X POST http://localhost:8080/api/inspection-tasks/1/start \
  -H "Content-Type: application/json" \
  -d '{"operator_id":2}'
curl -s -X POST http://localhost:8080/api/inspection-tasks/1/submit \
  -H "Content-Type: application/json" \
  -d '{"operator_id":2,"submission_note":"已提交"}'
```

**3. 创建样本并查询列表**

```bash
curl -s -X POST http://localhost:8080/api/samples \
  -H "Content-Type: application/json" \
  -d '{"sample_code":"SP-20260311-001","sample_type":"water","name":"测试水样","collector_id":2}'
curl -s http://localhost:8080/api/samples
```

**4. 创建样本结果**

```bash
curl -s -X POST http://localhost:8080/api/samples/1/results \
  -H "Content-Type: application/json" \
  -d '{"result_type":"salinity_test","raw_value":{"salinity":31.2,"unit":"ppt"},"normalized_value":{"salinity":31.2,"unit":"ppt","range_flag":"normal"},"conclusion":"盐度正常","entered_by":3}'
curl -s http://localhost:8080/api/samples/1/results
```

**5. 创建并解决异常**

```bash
curl -s -X POST http://localhost:8080/api/exceptions \
  -H "Content-Type: application/json" \
  -d '{"resource_type":"sample","resource_id":1,"category":"quality_issue","severity":"high","title":"样本标签模糊","reported_by":3}'
curl -s -X POST http://localhost:8080/api/exceptions/1/resolve \
  -H "Content-Type: application/json" \
  -d '{"resolved_by":1,"resolve_note":"已复核"}'
```

**6. 创建并查询分析任务**

```bash
curl -s -X POST http://localhost:8080/api/analysis-jobs \
  -H "Content-Type: application/json" \
  -d '{"sample_id":1,"job_type":"image_quality_check","params":{"mode":"standard"},"queued_by":3}'
curl -s http://localhost:8080/api/analysis-jobs/1
```

### 2.9.4 当前阶段显式传参策略

当前阶段为了避免认证系统阻塞业务 API 落地，以下身份字段允许由请求显式传入：

- `operator_id`
- `entered_by`
- `queued_by`
- `reported_by`
- `resolved_by`

这是一项临时策略，后续接入认证后应改为由服务端从当前用户上下文自动注入，接口字段语义保持不变。

### 2.9.5 Redis 接入边界说明

当前阶段 `analysis_jobs` 已完成以下基础：

- MariaDB 中记录分析任务请求
- 提供查询任务状态与结果摘要的接口
- 保留 `job_type`、`params_json` 等字段用于后续扩展

当前阶段尚未强制实现：

- PHP 创建任务后立即投递 Redis 队列
- Python 消费 Redis 任务并回写执行状态

这意味着当前实现不会阻碍后续接入 Redis/Python，但也不把该链路作为当前联调前置条件。

### 2.9.6 当前阶段前端联调说明

- `frontend/app/pages/index.vue` 已改为通过 `/api/dashboard/summary` 获取首页摘要数据。
- `frontend/nuxt.config.ts` 已增加开发态 `/api` 代理配置。
- `docker-compose.yml` 已为前端注入 `NUXT_DEV_API_PROXY_TARGET`，并为 PHP 注入数据库连接环境变量。

说明：

- 当前阶段接口侧联调已可通过 Nginx `http://localhost:8080/api/...` 完成。
- 若前端容器在特定网络环境下因依赖下载受阻，应优先保证 PHP API 与数据库链路可用，再单独处理前端依赖安装问题。

### 2.9.7 后续扩展切入点

以下能力已明确不属于当前 P0 实现，但已预留继续演进的边界：

- `analysis_jobs/retry`：建议采用“新建一条任务记录”而不是覆盖原任务。
- `samples/receive` 动作接口：当前样本状态推进由后端内聚处理，后续可补显式动作接口。
- 完整复核流：`sample_results.review_status` 已保留，可在后续增加 `submit-review / approve / reject` 接口。
- 任务事件表：当前尚未落地 `task_events`，后续可用于补齐更完整的审计与时间线能力。
