## 2.8 P0 MariaDB 建表 SQL 草案

本稿基于以下文档整理：

- `docs/2.4-MVP-API-范围冻结稿.md`
- `docs/2.5-P0-数据表实现稿.md`
- `docs/2.6-P0-API-字段草案.md`

目标是为当前阶段 `P0` 数据表提供第一版 `MariaDB` 建表 SQL 草案，用于后续迁移脚本、初始化数据和数据库落地讨论。

重要说明：

- 本文档为 SQL 草案，不代表已执行。
- 当前阶段仍然处于设计与实现准备阶段，未在仓库中实际落库。
- 若后续进入实施阶段，应结合实际 PHP 框架、迁移工具和 MariaDB 版本再做最终校准。

### 2.8.1 建表前置约定

建议数据库级默认设置：

```sql
CREATE DATABASE IF NOT EXISTS ocean
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

建议在目标数据库中执行：

```sql
USE ocean;
```

### 2.8.2 users

```sql
CREATE TABLE `users` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `username` VARCHAR(64) NOT NULL,
  `display_name` VARCHAR(100) NOT NULL,
  `email` VARCHAR(120) NULL,
  `status` VARCHAR(20) NOT NULL DEFAULT 'active',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_users_username` (`username`),
  KEY `idx_users_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

CREATE TABLE `user_roles` (

### 2.8.10 初始化数据草案

```sql
INSERT INTO `roles` (`code`, `name`) VALUES
  ('inspector', '巡检员'),
  ('analyst', '分析员'),
  ('admin', '管理员');
```

可选的测试用户数据：

```sql
INSERT INTO `users` (`username`, `display_name`, `email`, `status`) VALUES
  ('admin', '系统管理员', 'admin@example.com', 'active'),
  ('inspector01', '巡检员01', 'inspector01@example.com', 'active'),
  ('analyst01', '分析员01', 'analyst01@example.com', 'active');
```

可选的角色绑定草案：

```sql
INSERT INTO `user_roles` (`user_id`, `role_id`)
SELECT u.id, r.id
FROM `users` u
JOIN `roles` r ON (
  (u.username = 'admin' AND r.code = 'admin') OR
  (u.username = 'inspector01' AND r.code = 'inspector') OR
  (u.username = 'analyst01' AND r.code = 'analyst')
);
```

### 2.8.11 当前阶段实现注意点

- `sample_code` 当前阶段允许人工填写，因此创建样本时必须检查唯一性冲突。
- `operator_id`、`entered_by`、`queued_by`、`reported_by`、`resolved_by` 当前阶段允许显式传参，后续接入认证后再逐步改为服务端注入。
- `sample_results` 当前阶段仍以 `status` 为主流程状态，`review_status` 仅为预留字段。
- `analysis_jobs` 若后续实现 `retry`，建议新建一条新任务记录，而不是覆盖原失败任务。
- `exceptions.resource_type + resource_id` 不做数据库级外键，需由应用层保证引用合法。

### 2.8.12 当前阶段未纳入 SQL 草案的表

以下表不进入当前 `P0` 建表 SQL：

- `attachments`
- `task_events`
- `result_reviews`
- `audit_logs`
- `sample_batches`
- `equipment`
- `dictionaries`

这样可以确保当前阶段先把主业务对象、状态流转和异步任务的数据库基础建稳。
